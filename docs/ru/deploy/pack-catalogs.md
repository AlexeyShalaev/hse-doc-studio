# Каталоги паков

<p class="hds-lede">В мастере проекта видны паки, вшитые в образ Студии. Свои паки (другой программы, кафедры, вуза) можно вести в своём git-репозитории и править в Студии шаблонов. Раздел «Каталоги паков» в админке подключает такие паки к этой установке: они появляются в мастере проекта без пересборки образа и без перезапуска.</p>

## Источники

| Источник | Что указать | Когда |
|---|---|---|
| Git | адрес репозитория, папку паков (по умолчанию `packs`), тег, ветку или sha (пусто: ветка по умолчанию), доступ | репозиторий доступен серверу |
| Архив | файл .zip или .tar.gz с папкой паков | закрытый контур без доступа к хостингу |

Доступ к закрытому репозиторию: ваш личный доступ из «Доступов git» (токен для этого хоста) или служебный доступ репозитория из раздела «Студия шаблонов». К открытому репозиторию доступ не нужен.

Локально (Студия на своём компьютере) админки нет: в Студии шаблонов у рабочего пространства над папкой есть кнопка **Подключить к каталогу этой Студии**, дальше всё так же.

## Проверить и применить

1. **Добавить источник.** После добавления сразу откроется проверка.
2. **Проверить.** Студия скачивает выбранную ревизию, разбирает паки своим загрузчиком в отдельном процессе с ограничением времени и памяти, гоняет линтер паков и проверку неизменности выпусков и показывает план:

    | Пометка | Что значит |
    |---|---|
    | появится | новая выпущенная версия, после «Применить» она будет в мастере |
    | уже есть | эта версия уже в каталоге с тем же содержимым |
    | изменена в источнике | версия с этим номером уже в каталоге, но содержимое другое; применить нельзя |
    | не для этой Студии | нужна Студия новее (`min_studio`) или формат манифеста незнаком; появится после обновления Студии |
    | с ошибками | линтер нашёл ошибки или каталог версии изменён после выпуска |
    | не выпущена | версии нет в `releases.yaml` источника; в каталог попадают только выпущенные |

3. **Применить.** Применяется ровно проверенная ревизия. Если источник изменился после проверки, Студия попросит проверить снова. Версии кладутся в хранилище, каталог переключается сразу во всех процессах сервера.

Применить нельзя, если пак с тем же id уже вшит в Студию (нужна галочка **Заменить встроенный**), если пак уже несёт другой источник, если версия изменена в источнике или у новой версии ошибки.

## Неизменность

- Версия, которой пользуются проекты, не удаляется и не подменяется. Хранилище только дополняется: каждая версия лежит по своему дайджесту в `data_dir/packs-store`.
- Тот же номер с другим содержимым даёт отказ «версия изменена в источнике». Исправление в паке это новая версия.
- **Выключить** прячет паки источника из мастера проекта, **Удалить** убирает сам источник. Версии остаются: существующие проекты открываются и собираются как раньше.
- Пак с id вшитого пака подключается только с галочкой **Заменить встроенный**. Вшитые версии остаются для проектов, мастер предлагает версии источника.

## Отслеживание

Галочка **Отслеживать раз в сутки** у источника git: раз в сутки Студия проверяет ревизию и применяет новые выпущенные версии, если план чистый. Если что-то мешает, ничего не применяется, ошибка видна у источника и в истории. Проверка идёт от имени администратора, который подключил источник (его доступ git).

## Сборка на раннерах

Раннерам (встроенному, раннерам кластера и личным) паки не нужны: при создании проекта файлы шаблона копируются в папку проекта, а перед каждой сборкой сервер обновляет динамические файлы (`meta.tex`) и отдаёт раннеру проект целиком. Поэтому проект на подключённом паке собирается везде, где собирается проект на вшитом.

## История и аудит

У каждого источника есть **История**: добавление, правки, проверки, применения, выключение, отслеживание. Те же действия пишутся в журнал аудита установки (`pack_catalog.source_add`, `pack_catalog.source_update`, `pack_catalog.check`, `pack_catalog.apply`, `pack_catalog.source_enable`, `pack_catalog.source_disable`, `pack_catalog.source_remove`, `pack_catalog.track`).

## Пределы и безопасность

| Переменная | По умолчанию | Что ограничивает |
|---|---|---|
| `HSE_STUDIO__PACK_CATALOG__MAX_ARCHIVE_BYTES` | 100 МиБ | размер архива и объём скачанного из git |
| `HSE_STUDIO__PACK_CATALOG__MAX_FILES` | 20 000 | число файлов в ревизии |
| `HSE_STUDIO__PACK_CATALOG__MAX_BYTES` | 512 МиБ | общий размер файлов ревизии |
| `HSE_STUDIO__PACK_CATALOG__INSPECT_TIMEOUT_S` | 120 | время разбора ревизии |

Архив с символьными ссылками, абсолютными путями или выходом за свою папку не принимается целиком. Git скачивается без хуков, подмодулей и ссылок, только папка паков. Шаблоны пака исполняются только в песочнице.
