# Раннеры

<p class="hds-lede">Раннер выполняет задачи сборки, упаковки сдачи, проверки подписей и конвертации офисных файлов. Он сам опрашивает api по HTTPS: входящих соединений к раннеру не нужно.</p>

## Как работает задача

1. api кладёт задачу в очередь Postgres: справедливо по пользователям, одинаковые ожидающие задачи вытесняют друг друга.
2. Раннер забирает задачу долгим опросом и получает аренду на 45 секунд; пока он жив, он продлевает её каждые 10 секунд. Умерший раннер теряет задачу, она возвращается в очередь до двух повторов.
3. Входом служит манифест файлов и блобы по sha256. Раннер скачивает недостающее в свой кэш и проверяет хеши.
4. Результат раннер отправляет api, тот проверяет и применяет его. Раннер не пишет в базу и том проектов напрямую.

## Подключение раннера

1. В админке откройте «Раннеры» и выпустите **токен регистрации**: подпись, срок (по умолчанию 24 часа) и число использований.
2. На машине раннера задайте окружение:

   | Переменная | Значение |
   |---|---|
   | `HSE_RUNNER__API_URL` | адрес Студии, `https://studio.example.org` |
   | `HSE_RUNNER__TOKEN` | токен регистрации |
   | `HSE_RUNNER__NAME` | имя в списке (по умолчанию имя хоста) |
   | `HSE_RUNNER__CONCURRENCY` | сколько задач одновременно |
   | `HSE_RUNNER__DATA_DIR` | рабочие папки и кэш блобов |
   | `HSE_RUNNER__OFFICE_URL` | адрес Gotenberg; без него офисные задачи не берутся |

3. Запустите `hse-doc-studio runner` (в образе это та же команда).
4. Раннер меняет токен регистрации на собственный и сохраняет его в `data_dir/identity.json`. После этого `HSE_RUNNER__TOKEN` можно убрать из окружения.

В compose первый раннер регистрируется токеном `RUNNER_BOOTSTRAP_TOKEN`.

## Управление

В списке видны версия, теги, ёмкость и время последнего опроса.

- **Пауза** останавливает выдачу новых задач, текущие дорабатываются.
- **Ротация токена** выдаёт новый токен раннера; старый перестаёт работать. Новый токен задайте переменной `HSE_RUNNER__RUNNER_TOKEN`: она перекрывает `identity.json`.
- **Отзыв** навсегда закрывает раннеру доступ. Токен регистрации тоже можно отозвать до использования.
- Версии api и раннера проверяются при регистрации; несовместимый раннер отклоняется.
- Новый раннер после регистрации согласует с api возможности (`/announce`): ретрансляцию ИИ, отдельные слоты под неё и сообщение об остановке. Со старым api, который такого вызова не знает, раннер работает по-прежнему, без ретрансляции; старый раннер с новым api тоже работает.

## ИИ через свой раннер

Сервер не ходит во внутреннюю сеть пользователей. Чтобы пользоваться моделью на своём железе (Ollama, vLLM, LM Studio, любой OpenAI-совместимый адрес), хозяин личного раннера объявляет адреса в окружении раннера, а на сайте заводит провайдера «Через мой раннер». Сервер знает только имя адреса, URL и ключ остаются у раннера.

| Переменная | Значение |
|---|---|
| `HSE_RUNNER__AI_ENDPOINTS` | JSON-список адресов: `[{"name":"ollama","url":"http://localhost:11434/v1","flavor":"ollama"},{"name":"vllm","url":"http://gpu.lan:8000/v1","key_env":"VLLM_API_KEY"}]` |
| `HSE_RUNNER__AI_CONCURRENCY` | сколько запросов к моделям раннер ведёт сразу (по умолчанию 2), отдельно от сборок |
| `HSE_RUNNER__RELAY_MAX_RESPONSE_BYTES` | предел ответа модели (по умолчанию 64 MiB) |

- `name`: латиница в нижнем регистре, цифры, `-` и `_`, до 32 символов; так адрес называется в форме провайдера.
- `flavor`: `openai` (по умолчанию) или `ollama` (без `tool_choice` и `stream_options`, как требует Ollama).
- `key_env`: имя переменной окружения раннера с ключом модели; ключ на сервер не уходит.
- Раннер ходит только на объявленные адреса и только по путям `models`, `chat/completions`, `completions`, `embeddings`; заголовки сервера не пересылаются, редиректы не следуются.
- Ретрансляцией пользуется только хозяин раннера. Без объявленных адресов раннер ретрансляцию не берёт.

Пределы на стороне api: `HSE_STUDIO__JOBS__RELAY_PICKUP_S` (сколько ждать, пока раннер возьмёт запрос), `HSE_STUDIO__JOBS__RELAY_MAX_REQUEST_BYTES`, `HSE_STUDIO__JOBS__RELAY_MAX_RESPONSE_BYTES`, `HSE_STUDIO__JOBS__RELAY_MAX_PENDING_PER_USER`, `HSE_STUDIO__JOBS__RELAY_MAX_DURATION_S`. Раннер, который не ответил, в чате видно сообщением «Раннер «…» не ответил» с выбором другой модели.

## Масштабирование

Несколько раннеров на разных машинах работают сообща. Две реплики на одной машине должны иметь разные каталоги данных. Кроме раннеров установки бывают личные раннеры пользователей; раннеров организаций пока нет.
