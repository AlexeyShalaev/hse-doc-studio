# Официальные паки без аккаунта GitHub

<p class="hds-lede">В Студии шаблонов есть карточка «Официальные паки»: паки из репозитория самой Студии, которые правят мышкой и предлагают через PR. Человек со своим токеном GitHub отправляет изменения через свой форк. Людям без аккаунта GitHub администратор может дать служебный аккаунт установки (бота): ветка уходит в форк бота, PR открывается из форка, а в описании PR стоит имя автора из профиля Студии.</p>

## Что делает бот и чего не делает

- Отправляет ветку **только в свой форк**. В официальный репозиторий Студия ничего не отправляет, даже если у бота есть на это право.
- Открывает PR из форка в официальный репозиторий. Автор коммитов это человек: имя из профиля, адрес noreply Студии, настоящая почта не раскрывается.
- Работает только для людей с правом «Автор шаблонов» (выдаётся в разделе «Студия шаблонов» админки).
- Не даёт предложить ветку, которая меняет что-то вне папки паков.
- Не больше заданного числа предложений на человека за сутки (по умолчанию 5).
- Каждое использование токена и каждое предложение пишется в журнал аудита (`pack_studio.service_access_use`, `pack_studio.proposed`).

## Какой нужен токен

Нужен **классический токен GitHub (Personal access token, classic) с областью `public_repo`**.

Точный токен (fine-grained) не подойдёт: GitHub не даёт ему вносить вклад в открытые репозитории, где владелец токена не участник, поэтому PR из форка в официальный репозиторий им не открыть. Области `repo` и `workflow` не нужны: паки не трогают `.github/workflows`, а репозиторий открытый.

## Настройка шаг за шагом

1. **Заведите отдельный аккаунт GitHub для бота**, например `hse-doc-studio-bot` у вашей установки. Личный аккаунт администратора не подходит: от его имени будут открываться чужие PR.
2. Включите в аккаунте бота двухфакторную аутентификацию и сохраните коды восстановления в хранилище секретов.
3. В аккаунте бота откройте **Settings, Developer settings, Personal access tokens, Tokens (classic)**, нажмите **Generate new token (classic)**.
    - Note: например `HSE Doc Studio, официальные паки`.
    - Expiration: срок по вашей политике (например 90 дней); перед истечением выпустите новый и замените доступ.
    - Scopes: отметьте только **`public_repo`**.
4. Скопируйте токен (`ghp_...`). GitHub показывает его один раз.
5. В Студии откройте **Админка, Студия шаблонов, Официальные паки** и нажмите **Добавить бота**. Адрес официального репозитория уже подставлен, галочка **Только через форк (бот)** стоит. Вставьте токен и сохраните. Токен шифруется и обратно не показывается.
6. В списке **Служебные доступы** нажмите у бота **Проверить**. Проверка покажет аккаунт токена, его области и создаст форк в аккаунте бота (или найдёт существующий). Если проверка называет проблему, исправьте её:

    | Проблема | Что сделать |
    |---|---|
    | точный токен | выпустить классический токен (шаг 3) |
    | нет области `public_repo` | выпустить токен заново с этой областью |
    | GitHub не принял токен | токен отозван или истёк: выпустить новый |
    | форк не удалось создать | проверить область и что у бота нет репозитория с тем же именем |
    | у бота есть право записи | не мешает, но лучше убрать бота из соавторов официального репозитория |

7. Выдайте право «Автор шаблонов» людям или группам организаций. После этого в Студии шаблонов в карточке «Официальные паки» появится вариант **Без своего аккаунта GitHub**.

## Выключатель и лимит

В разделе **Официальные паки** админки:

- **Вклад без аккаунта GitHub** выключает бота целиком: предложения через него отклоняются, своим токеном предлагать изменения можно и дальше.
- **Предложений на человека в сутки** защищает от спама от имени бота. Счёт идёт по журналу аудита за последние 24 часа. Значение по умолчанию задаёт переменная `HSE_STUDIO__PACK_STUDIO__OFFICIAL_BOT_DAILY_LIMIT`.

## Свой официальный репозиторий

Официальный репозиторий задают переменные окружения:

| Переменная | По умолчанию |
|---|---|
| `HSE_STUDIO__PACK_STUDIO__OFFICIAL_REPO_URL` | `https://github.com/AlexeyShalaev/hse-doc-studio` |
| `HSE_STUDIO__PACK_STUDIO__OFFICIAL_PACKS_PATH` | `packs` |
| `HSE_STUDIO__PACK_STUDIO__OFFICIAL_BASE_BRANCH` | `master` |
| `HSE_STUDIO__PACK_STUDIO__OFFICIAL_LICENSE` | `Apache-2.0` |

Форк Студии указывает свой репозиторий; пустой `OFFICIAL_REPO_URL` прячет карточку «Официальные паки».

## Что видят люди

- Перед первой отправкой Студия просит согласиться, что вклад публичен и идёт под лицензией репозитория, и даёт ссылку на правила вклада.
- У PR из форка нового участника GitHub не запускает проверки, пока сопровождающий репозитория не одобрит запуск. Студия так и пишет: «ждут одобрения», а не вечное «ожидает».
- Официальные паки выходят вместе со Студией: после слияния PR Студия пишет, что новая версия появится у пользователей со следующим выпуском.
