# Студия шаблонов у себя

<p class="hds-lede">Студия шаблонов правит паки мышкой и в редакторе, собирает предпросмотр на тестовых данных и отправляет изменения запросом на слияние. Своего сервера для этого не нужно: тот же образ Студии запускается у вас в профиле «только Студия шаблонов». Входа и регистрации нет, пользователь один (вы), проекты скрыты.</p>

## Что нужно

- Docker: Docker Desktop на macOS и Windows, Docker Engine на Linux.
- Место на диске под образ TeX Live (несколько гигабайт). Он скачивается фоном после первого запуска и нужен для предпросмотра.
- Папка с паками (`pack.yaml` в папке пака, сами паки в корне папки или в подпапке `packs/`). Для своего репозитория git папка не нужна, его можно добавить в интерфейсе.

## Запуск

Положите файл профиля в отдельную папку и укажите в `.env`, где лежат паки:

```sh
mkdir -p ~/hse-pack-studio && cd ~/hse-pack-studio
curl -fsSLO https://raw.githubusercontent.com/AlexeyShalaev/hse-doc-studio/master/deploy/pack-studio/docker-compose.yml
echo "PACKS_DIR=$HOME/my-packs" > .env
docker compose up -d
```

Откройте <http://localhost:17260>. Сразу открывается Студия шаблонов, папка паков уже есть в списке рабочих пространств.

- Без `PACKS_DIR` открывается папка, из которой запущена команда.
- Данные (клоны репозиториев, доступы git, сборки предпросмотра) лежат в `~/.hse-pack-studio`, другая папка задаётся `DATA_DIR`.
- Остальные переменные (порт, образ TeX, шрифты) описаны в [`.env.example`](https://github.com/AlexeyShalaev/hse-doc-studio/blob/master/deploy/pack-studio/.env.example).

!!! note "Linux"
    Студия пишет в папку паков и в `DATA_DIR` от своего пользователя. Запустите её своим uid и дайте доступ к сокету Docker, добавив в `.env`:

    ```sh
    echo "HSE_UID=$(id -u)" >> .env
    echo "HSE_GID=$(id -g)" >> .env
    echo "DOCKER_GID=$(stat -c '%g' /var/run/docker.sock)" >> .env
    ```

!!! note "macOS"
    Docker Desktop не отдаёт контейнерам системные шрифты (Times New Roman, Arial): без них предпросмотр собирается со свободными заменами. Скопируйте шрифты в папку под домашним каталогом и укажите её в `HOST_FONTS_DIR` (пример в `.env.example`) или загрузите их в **Настройках, «Шрифты»**.

!!! note "Windows"
    Создайте `.env` с абсолютным путём, например `PACKS_DIR=C:/Users/me/my-packs`, и запустите `docker compose up -d` в PowerShell.

## Что дальше

1. **Папка паков.** Откройте пространство, выберите файл версии (`version.yaml`) и нажмите **Собрать** во вкладке предпросмотра. Первая сборка ждёт образ TeX.
2. **Свой репозиторий паков.** Добавьте токен в **Настройках, «Доступы git»**, затем **Новое рабочее пространство**, вкладка git: адрес репозитория и токен. Правки уходят в ветку, кнопка **Предложить изменения** открывает PR (GitHub) или MR (GitLab).
3. **Официальные паки.** Карточка **Официальные паки**, кнопка **Начать**: паки из репозитория Студии, изменения уходят через ваш форк вашим токеном GitHub. Правила вклада в разделе «Contributing to the official packs» файла [CONTRIBUTING.md](https://github.com/AlexeyShalaev/hse-doc-studio/blob/master/CONTRIBUTING.md#contributing-to-the-official-packs).
4. **Устройство пака.** Файлы, версии и что считается patch, minor и major: [Пак и шаблоны](../reference/pack.md).

## Обновление и остановка

```sh
docker compose pull && docker compose up -d   # новая версия Студии
docker compose down                           # остановить, данные остаются
```

## Разработчикам Студии

В рабочей копии репозитория `make pack-studio` поднимает то же самое из исходников: api и Vite на <http://localhost:3001/pack-studio>, рабочее пространство над `packs/` рабочей копии, данные в `.pack-studio/`. Сборке предпросмотра нужен локальный Docker.
