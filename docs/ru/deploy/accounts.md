# Люди и вход

<p class="hds-lede">Всё ниже настраивается в админке (`/admin`) или переменными окружения. Заданное в окружении блокирует правку в интерфейсе.</p>

## Режимы регистрации

| Режим | Кто может зарегистрироваться |
|---|---|
| `open` | любой, у кого есть доступ к адресу |
| `domains` | только адреса из списка доменов почты |
| `invite` | только по приглашению |
| `closed` | никто; аккаунты заводит администратор |

Поверх любого режима включается **одобрение**: новый аккаунт ждёт решения администратора в разделе «Одобрения» и до этого не входит.

Окружение: `HSE_STUDIO__AUTH__REGISTRATION_MODE`, `..._REGISTRATION_DOMAINS`, `..._REQUIRE_APPROVAL`, `..._PASSWORD_ENABLED`.

## Приглашения

Администратор вводит адрес, Студия отправляет письмо со ссылкой. Приглашение можно отправить повторно или отозвать. Без настроенной почты приглашения не уходят.

## Почта (SMTP)

Раздел «Почта» в админке или `HSE_STUDIO__MAIL__*`. Пароль SMTP принимается на запись и никогда не возвращается. Кнопка «Тестовое письмо» отправляет письмо на адрес аккаунта администратора. Письма идут через очередь (outbox), сбой SMTP не теряет письмо.

Почта нужна для приглашений, подтверждения адреса и сброса пароля.

## Единый вход (OIDC)

В разделе «Вход» добавьте провайдера:

| Поле | Значение |
|---|---|
| Название | текст на кнопке входа |
| Issuer | адрес провайдера, по нему находится `/.well-known/openid-configuration` |
| Client ID, Client secret | выдаются провайдером; секрет хранится зашифрованным и не показывается |
| Scopes | по умолчанию `openid email profile` |
| Автосоздание | создавать аккаунт при первом входе |

!!! note "Состояние"
    Настройка провайдеров уже есть в админке. Сам вход через провайдера включается вместе с финальным срезом этапа 2; redirect URI для регистрации у провайдера и порядок привязки существующих аккаунтов проверьте в заметках релиза, с которого вход заработал.

Пароль можно выключить (`password_enabled`) только когда включён хотя бы один провайдер: иначе в Студию нельзя войти.

Если провайдер живёт во внутренней сети, добавьте его хост в `HSE_STUDIO__EGRESS__ALLOWLIST`: исходящие запросы к приватным адресам по умолчанию закрыты.

## Пользователи

В разделе «Люди»: поиск, отключение и включение, завершение всех сессий пользователя.

Сессии: непрозрачный идентификатор в HttpOnly-cookie, скользящий срок 7 суток, предел 30 суток (`SESSION_IDLE_DAYS`, `SESSION_ABSOLUTE_DAYS`). Пароли хранятся как argon2id, длина от 10 символов.

### Сброс пароля

Пользователь сбрасывает пароль сам через письмо. Если письмо недоступно, администратор может выдать ссылку сброса. Это **break-glass**: нужно подтверждение, событие пишется в аудит, пользователю уходит письмо-уведомление. Администратор не получает доступа к проектам пользователя этим действием, но может войти под новым паролем, поэтому пользуйтесь им как крайней мерой.

## Аудит

Раздел «Аудит» хранит события входа, смены прав, выдачи ссылок сброса, действий с раннерами и настроек. Срок хранения: `HSE_STUDIO__SERVER__AUDIT_RETENTION_DAYS` (по умолчанию 365, 0 значит бессрочно).

## Токены доступа

Пользователь выпускает личные токены в настройках аккаунта для CLI и скриптов. Токен показывается один раз, в базе лежит только хеш. Токен не может управлять токенами и освобождён от CSRF-проверки.
