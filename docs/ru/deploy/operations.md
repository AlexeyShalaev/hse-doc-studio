# Бэкап, обновление, потеря ключа

## Что копировать

| Что | Как |
|---|---|
| база | `docker compose exec postgres pg_dump -U studio studio > studio.sql` |
| исходники проектов | том `api-data` (`projects_root`) |
| блобы, входы и выходы задач | бакет S3 или том `minio-data` |
| ONLYOFFICE | том `onlyoffice-data`, если сервис включён |
| ключ `SECRETS_KEY` | **отдельно** от дампов, в менеджере секретов |

База и том проектов должны копироваться согласованно: сначала остановите запись или снимите снимок обоих. Периодически проверяйте восстановление на пустой машине.

## Обновление

compose: смените `TAG`, затем `docker compose pull && docker compose up -d`. Миграции базы выполняет api на старте под advisory-блокировкой.

Helm: `helm upgrade`; Job миграций запускается перед обновлением. Задавайте `secrets.existingSecret`, чтобы Job видел актуальные секреты.

Перед обновлением снимите бэкап. Раннеры обновляйте вместе с api: несовместимая версия отклоняется при регистрации. Проверка схемы: `hse-doc-studio db current` и `hse-doc-studio db check`.

Одновременно работает одна реплика api; обновление кратко прерывает доступ.

## Потеря ключа

`SECRETS_KEY` (Fernet) шифрует секреты в базе: токены git, пароль SMTP, секреты OIDC, ключи провайдеров ИИ и подпись. Ключ нигде не хранится рядом с базой, чтобы украденный дамп не раскрывал секреты.

**Если ключ потерян, секреты восстановить нельзя.** Что происходит:

- пользователи, проекты, права, сборки и сами документы **не страдают**: они не зашифрованы этим ключом;
- сохранённые секреты нечитаемы: SMTP, OIDC, токены git, ключи ИИ.

Как восстановиться:

1. Сгенерируйте новый ключ и задайте его в `SECRETS_KEY`.
2. Заново введите пароль SMTP и секреты OIDC в админке.
3. Пользователям нужно заново ввести токены git и ключи ИИ в настройках.
4. Храните копию нового ключа вне бэкапа базы.

## Смена ключа

Если ключ нужно заменить, а старый известен:

1. Задайте новый ключ как первичный, а прежний передайте в `HSE_STUDIO__SECRETS__RETIRED_KEYS`.
2. Проверьте объём: `hse-doc-studio secrets reencrypt --dry-run`.
3. Выполните `hse-doc-studio secrets reencrypt`. Команда выводит число перешифрованных записей и нечитаемых. При сообщении «изменилась во время работы» запустите её ещё раз.
4. Когда нечитаемых нет, уберите прежний ключ из `RETIRED_KEYS`.

## Если что-то пошло не так

- старт без БД перечисляет, чего не хватает; смотрите журнал api;
- `GET /health/ready` с `HEALTH_TOKEN` показывает, какая проверка красная;
- раннер не берёт задачи: проверьте раздел раннеров в админке, паузу, версию и доступ к `API_URL`; за прокси убедитесь в таймауте не меньше 60 секунд.
