# Серверы ИИ-моделей

<p class="hds-lede">Админка (`/admin`, раздел «Серверы моделей») ставит сервер модели, запускает его в соседнем Docker-контейнере и сразу заводит общего ИИ-провайдера, которым пользуются все.</p>

Страница доступна только администратору инстанса. Работает в режиме общего сервера.

## Движки

| Движок | Для чего | Нужна ли видеокарта |
|---|---|---|
| Ollama | проще всего начать, модели из библиотеки ollama.com | нет, на процессоре медленнее |
| vLLM | быстрый OpenAI-совместимый сервер, модели с Hugging Face | да, NVIDIA |
| SGLang | то же для OpenAI-совместимого API, модели с Hugging Face | да, NVIDIA |

Страница показывает по данным пробы железа: видеокарту и её память, оперативную память, ядра, архитектуру и свободное место. Движок, которому не хватает карты, помечен причиной и не устанавливается (API отвечает `409 model_server_engine_requires_gpu`).

## Оценка до скачивания

Для выбранной модели Студия считает по числу параметров и квантованию, сколько памяти и диска нужно, и сравнивает с железом: «поместится», «впритык», «не поместится», «размер неизвестен». Оценка приблизительная: реальное потребление зависит от длины контекста и числа одновременных запросов. Модель, которая заведомо не поместится, не ставится без явного подтверждения.

Модель выбирается из короткого каталога либо вводится по имени: тег библиотеки Ollama (`qwen3:8b`) или идентификатор на Hugging Face (`Qwen/Qwen3-8B`).

## Что происходит при установке

1. Запускается контейнер движка (образ задаётся настройкой, по умолчанию официальный). Если видна карта NVIDIA и NVIDIA Container Toolkit, контейнер получает GPU. Ollama при отказе GPU запускается на процессоре, vLLM и SGLang нет.
2. Дожидаемся готовности движка. Для Ollama скачивается модель, ход загрузки виден по шагам. vLLM и SGLang скачивают веса при старте, поэтому «готов» наступает позже, а в журнале видны строки контейнера.
3. Создаётся общий ИИ-провайдер (Ollama для Ollama, OpenAI-совместимый для vLLM и SGLang) с адресом `/v1` контейнера и моделью.
4. Проверка «модель отвечает»: короткий запрос на дополнение. Если модель ещё грузится в память, шаг помечается предупреждением, а сервер и провайдер остаются.

Одновременно идёт одна установка (`HSE_STUDIO__MODEL_SERVERS__MAX_CONCURRENT_INSTALLS`). Ход установки и журнал шагов хранятся в памяти процесса: после перезапуска Студии они исчезают, а сами серверы остаются и находятся по меткам контейнеров.

Дальше сервер можно остановить, запустить, посмотреть журнал контейнера и удалить. Удаление убирает и провайдера. Тома с весами по умолчанию остаются; отметка «удалить и скачанные модели» очищает том движка, если его не делят другие серверы того же движка.

## Безопасность

- Контейнер не публикуется наружу: в общей сети Docker он виден только Студии, без неё порт открыт лишь на `127.0.0.1` хоста.
- vLLM и SGLang запускаются с ключом API. Ключ генерируется (32 байта), хранится зашифрованно как ключ общего провайдера и не показывается ни в ответах API, ни в журнале аудита.
- Токен Hugging Face (нужен для закрытых и gated-моделей vLLM и SGLang) хранится только зашифрованно под ключом секретов Студии. В интерфейсе и API видно лишь факт наличия: заменить и удалить можно, прочитать нельзя. В ответы, журналы и аудит он не попадает (аудит пишет только факт `model_server.hf_token_set` / `model_server.hf_token_clear`).
- Секреты контейнера (ключ API, токен Hugging Face) передаются через временный файл с правами `0600`, который удаляется сразу после запуска, а не аргументами процесса.
- События `model_server.install`, `.start`, `.stop`, `.remove` попадают в журнал аудита: движок, модель, цель, без секретов.
- Установка требует доступа Студии к `docker.sock` хоста. Сокет равен root на хосте: давайте его только установке, которой вы доверяете.

## Установка на другой машине по SSH

В форме выберите «На другой машине по SSH». Вход, подтверждение отпечатка ключа хоста, защита от обращений во внутреннюю сеть (SSRF), ограничение частоты, одноразовые или зашифрованно сохранённые доступы и ход по шагам общие с [установкой раннеров](runners.md): слой один, отдельного SSH для моделей нет.

1. Студия получает ключ хоста, вы сверяете отпечаток с тем, что показывает сама машина.
2. Студия входит с закреплённым ключом, определяет систему и Docker (при необходимости ставит Docker, если вы разрешили).
3. Шаги: видеокарта (`nvidia-smi`; для vLLM и SGLang нужна NVIDIA), контейнер движка, модель, провайдер, проверка «модель отвечает».

**Доступ к серверу.** По умолчанию контейнер публикуется только на `127.0.0.1` удалённой машины: из интернета и из соседних сетей его не видно. Студия до такого сервера не достучится, поэтому ИИ-провайдер для него **не регистрируется**; сервером пользуются на самой машине. Режим «Из сети (с ключом API)» открывает порт на всех интерфейсах, требует явного подтверждения, создаёт ключ API (хранится зашифрованно у провайдера) и регистрирует общий ИИ-провайдер в Студии. Для Ollama этот режим недоступен: у неё нет ключа API. Не открывайте порт в интернет без нужды; ограничьте его межсетевым экраном до адреса Студии.

**Состояние в базе.** Серверы (локальные и по SSH) записываются в таблицу `model_servers` на каждом шаге, поэтому ход установки и список переживают перезапуск Студии. Установка, оборванная перезапуском, показывается как «Ошибка: прервана перезапуском». В записи нет секретов.

**Управление позже.** Запуск, остановка, журнал и удаление сервера по SSH работают, если при установке отмечено «Сохранить доступ зашифрованно». Без сохранённого доступа запись видна, но управлять сервером отсюда нельзя: удаление убирает запись и провайдера, а контейнер на машине остаётся (уберите его сами: `docker rm -f hse-ms-<id>`).

Секреты на удалённой машине: ключ API и токен Hugging Face передаются через stdin во временный файл с правами `0600`, который удаляется сразу после `docker run`. В аргументах команд, журнале аудита и ответах API их нет. Аудит: `runner_install.ssh.*` (общий слой) и `model_server.*`.

## Kubernetes

**В Kubernetes локальная установка не поддерживается.** В Helm-чарте она выключена: `modelServers.local.enabled: false` (`HSE_STUDIO__MODEL_SERVERS__LOCAL_ENABLED=false`). Причина: установка запускает соседние контейнеры через docker.sock узла, а под api его не получает (сокет равен root на узле и ломает Pod Security restricted, поэтому чарт его не монтирует). Страница делает вариант «на машине со Студией» недоступным, API отвечает `409 model_server_local_install_disabled`. Включить значение можно только с ручной правкой чарта (hostPath-монтирование сокета в под api на выделенном узле), и это на вашей ответственности. Для кластера используйте установку на отдельной машине по SSH или внешний сервер модели, добавленный как обычный ИИ-провайдер.

## Настройки

| Переменная | Назначение |
|---|---|
| `HSE_STUDIO__MODEL_SERVERS__LOCAL_ENABLED` | разрешить установку рядом со Студией (по умолчанию да, в Helm нет) |
| `HSE_STUDIO__MODEL_SERVERS__OLLAMA_IMAGE`, `..._VLLM_IMAGE`, `..._SGLANG_IMAGE` | образы движков; пусто значит образ по умолчанию с закреплённым тегом (Ollama 0.40.15, vLLM v0.32.0, SGLang v0.5.23) |
| `HSE_STUDIO__MODEL_SERVERS__MAX_CONCURRENT_INSTALLS` | число одновременных установок |
| `HSE_STUDIO__MODEL_SERVERS__STARTUP_TIMEOUT_S`, `..._READY_TIMEOUT_S` | сколько ждать запуска и готовности (vLLM и SGLang при первой загрузке весов) |

Полный список переменных: [справочник](env-reference.md).
