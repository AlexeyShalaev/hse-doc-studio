# Самодиагностика сервера

<p class="hds-lede">Сервер сам раз в несколько минут проверяет базу, хранилище, раннеры, диск, сертификаты, бэкапы, почту и фоновые задачи. У каждой проверки есть статус, причина и подсказка, что делать. Админам приходит уведомление, только когда проблема устойчива.</p>

Устройство и принятые решения: `docs/design/self-diagnostics.md` в репозитории.

## Где смотреть

В админке: **Самодиагностика** (`/admin/diagnostics`). Вверху общий итог, ниже проверки по группам. Кнопка «Проверить сейчас» прогоняет всё, «Проверить» у строки одну проверку. Ручной прогон обновляет страницу, но уведомлений не рассылает.

Статусы: **В порядке**, **Предупреждение** (работает, но скоро будет плохо), **Сбой** (работа нарушена или данные под угрозой). «Не настроено» значит, что подсистемы нет (например, SMTP), в итог такая проверка не входит.

## Что проверяется

| Проверка | Что смотрит | Что делать при проблеме |
|---|---|---|
| База данных | доступность, версия, задержка | поднять Postgres, проверить `HSE_STUDIO__DB__*`, нагрузку на диск |
| Миграции базы | ревизия в базе против образа | перезапустить api (он мигрирует сам); образ старше базы значит запустить свежий образ |
| Объектное хранилище | запись, чтение и удаление пробного объекта | проверить ключи, бакет и места в `HSE_STUDIO__S3__*` |
| Диск и хранение данных | тома и база, как у контроля места, ошибки очистки | сократить сроки в «Хранение данных», расширить том |
| Раннеры | есть ли живые общие раннеры | зарегистрировать или перезапустить раннер |
| Очередь и зависшие задачи | ожидание в очереди, задачи с истёкшей арендой | добавить раннеров, включить автомасштабирование |
| Фоновые задачи | есть ли лидер, не застыли ли задачи | перезапустить api, проверить связь с базой |
| Сертификаты | срок публичного адреса (`auth.public_url`) и S3 | продлить сертификат, проверить автопродление |
| Бэкапы | давность последнего успешного, последняя попытка | снять вручную, проверить назначение и расписание |
| Почта (SMTP) | соединение и вход без отправки письма | проверить хост, порт и пароль |

Точная подсказка показана на странице под каждой проблемой.

## Пороги и уведомления

Внизу страницы: задержка базы и хранилища, ожидание в очереди, просрочка задачи, срок сертификата, давность бэкапа. «Сбросить к умолчаниям» возвращает заводские значения. Пороги места на диске общие с контролем места и правятся в «Хранение данных».

| Настройка | По умолчанию | Смысл |
|---|---|---|
| Подтверждение статуса | 2 прохода | сколько проверок подряд статус должен держаться до уведомления |
| Напоминание | 24 ч | как часто повторять про ту же проблему |
| Уведомлять админов | включено | сообщение во «Входящих» при переходе в предупреждение или сбой и при возвращении в норму |

Одиночный сбой и мигание статуса уведомлений не вызывают. Уведомление открывает страницу самодиагностики.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HSE_STUDIO__DIAGNOSTICS__ENABLED` | `true` | плановая проверка под лидерским локом |
| `HSE_STUDIO__DIAGNOSTICS__INTERVAL_S` | `300` | период проверки |
| `HSE_STUDIO__DIAGNOSTICS__CHECK_TIMEOUT_S` | `20` | предел времени одной проверки |
| `HSE_STUDIO__DIAGNOSTICS__PUBLIC_ENDPOINT` | `false` | открыть `/health/diagnostics` для мониторинга |

Полный список: [Переменные окружения](env-reference.md).

## Внешний мониторинг

**Публичный эндпоинт.** При `HSE_STUDIO__DIAGNOSTICS__PUBLIC_ENDPOINT=true` доступен `GET /health/diagnostics` без входа:

```json
{"status": "warn", "checked_at": "2026-11-05T10:00:01+00:00", "checks": {"database": "ok", "disk": "warn"}}
```

Только статусы по id проверок, без причин, значений и адресов. Код ответа `200` при `ok` и `warn`, `503` при `fail` и пока результатов нет (`"status": "unknown"`). Подключите его к UptimeRobot, Gatus или Zabbix.

**Метрики Prometheus** (`/metrics`, по токену `HSE_STUDIO__OBSERVABILITY__METRICS_TOKEN`):

| Метрика | Смысл |
|---|---|
| `hse_diag_check_status{check}` | 0 в порядке, 1 предупреждение, 2 сбой |
| `hse_diag_check_last_timestamp_seconds{check}` | когда проверка шла в последний раз |
| `hse_diag_check_duration_seconds{check}` | длительность последней проверки |
| `hse_diag_overall_status` | общий итог |

Метрики читают кэш процесса и свежи у лидера и у экземпляров, которых открывали страницей: при нескольких экземплярах снимайте со всех и берите максимум. Пример правила: `max(hse_diag_overall_status) >= 2` в течение 10 минут.

## Если страница пуста

«Проверок ещё не было» на только что запущенной установке нормально: первый проход через несколько секунд после старта лидера. Если так остаётся, смотрите проверку «Фоновые задачи» (нажмите «Проверить сейчас») и журнал `docker compose logs api`.
