# ИИ-клиенты (MCP)

<p class="hds-lede">Студия умеет работать сервером Model Context Protocol. Внешний ИИ-клиент (Claude Desktop, Claude Code, Cursor, VS Code, Zed) видит ваши проекты и работает в них инструментами Студии: читает и правит файлы, собирает PDF, разбирает замечания, сохраняет снимки. Он действует от вашего имени и не может больше, чем вы.</p>

## Включить

=== "Локальная Студия"

    **Настройки → ИИ-клиенты (MCP) → «Включить MCP-сервер»**. Адрес сервера `http://127.0.0.1:17240/mcp`: порт тот же, что у Студии. Токен не нужен: сервер отвечает только программам на этом компьютере и отклоняет запросы, где `Host` или `Origin` называют чужой сайт.

=== "Облачная Студия"

    MCP включает администратор: **Админка → MCP-сервер → «Включить MCP-сервер»**. Затем каждый выпускает себе токен: **Настройки → Аккаунт → Токены → Новый токен**, право **MCP**. Адрес сервера `https://<адрес Студии>/mcp`, токен передаётся заголовком `Authorization: Bearer <токен>`.

## Подключить клиента

Готовые конфиги с вашим адресом есть в Студии: **Настройки → ИИ-клиенты (MCP)**.

=== "Claude Code"

    ```bash
    # локально
    claude mcp add --transport http hse-doc-studio http://127.0.0.1:17240/mcp
    # облако
    claude mcp add --transport http hse-doc-studio https://studio.example.org/mcp \
      --header "Authorization: Bearer hsd_pat_..."
    ```

=== "Cursor, VS Code"

    ```json
    {
      "mcpServers": {
        "hse-doc-studio": {
          "url": "https://studio.example.org/mcp",
          "headers": { "Authorization": "Bearer hsd_pat_..." }
        }
      }
    }
    ```

    У VS Code ключ верхнего уровня `servers` и поле `"type": "http"`. Для локальной Студии `headers` не нужен.

=== "Claude Desktop и другие (stdio)"

    Клиенты, которые запускают сервер процессом, используют мост `hse-doc-studio mcp`: он пересылает запросы работающей Студии.

    ```json
    {
      "mcpServers": {
        "hse-doc-studio": {
          "command": "hse-doc-studio",
          "args": ["mcp", "--url", "https://studio.example.org"],
          "env": { "HSE_STUDIO_TOKEN": "hsd_pat_..." }
        }
      }
    }
    ```

    Без `--url` мост подключается к локальной Студии, она должна быть запущена.

## Что доступно

- **Инструменты.** Проекты (список, карточка, создание, метаданные, руководитель и авторы, обновление шаблона), файлы (дерево, чтение, поиск, правка, запись, перенос), сборка (запуск с ожиданием результата, история, лог, отмена), проверки и отчёт нормоконтроля, требования, ревью-комментарии (облако), история и git-синхронизация, профили и пакеты сдачи, состояние подписей. Инструменты проекта принимают `project_id`; начните с `list_projects`.
- **Ресурсы.** `studio://projects`, карточка проекта `studio://projects/<id>`, файлы `studio://projects/<id>/files/<путь>` и PDF сборок.
- **Сценарии (prompts).** `fix_build` (починить сборку), `normcontrol` (разобрать замечания), `review_changes` (описать изменения перед снимком).

### Проекты: создание, люди, проект из облака

- **`create_project`** создаёт проект из шаблона (`pack_id`, `template_id`, `version` из `list_templates`). В локальной Студии нужен `folder`, полный путь к новой папке. В облаке папку выбирает сервер: поля `folder` в схеме нет, а присланное значение не используется.
- **`set_project_people`** меняет научного руководителя (`supervisor`), соруководителя (`co_supervisor`), академического руководителя программы (`academic_supervisor`) и авторов, то есть то, что попадает на титульный лист, в заявку и заявление. Права те же, что в настройках проекта: нужна роль, которой можно менять настройки, а проект должен быть доступен для записи. Значения доходят до PDF при следующей сборке: `common/meta.tex` перегенерируется перед каждой сборкой.
    - У руководителей поля `name` (ФИО), `title` (должность), `degree` (степень или звание), `role` (`university` или `company`). Переданные поля заменяют текущие, остальные остаются; пустая строка очищает должность или степень, пустое `name` убирает человека из проекта.
    - `author` меняет одного автора, не трогая остальных: `name`, `group`, `email`, пустая строка очищает группу или e-mail. В командном проекте автора выбирают по `slug` из `get_project`, в одиночном меняется первый автор.
    - `authors` заменяет список целиком: `name`, `group` и `email` каждого автора, первый идёт на титульный лист. Чтобы у существующих авторов сохранились тема и комплект командного проекта, передайте их `slug` из `get_project`.
    - `clear: ["co_supervisor"]` убирает соруководителя (так же `supervisor` и `academic_supervisor`).
    - Пример: `{"supervisor": {"name": "С. А. Шершаков", "degree": "канд. техн. наук"}, "author": {"group": "МПИ251", "email": "ivanov@edu.hse.ru"}}`.
    - Каждое изменение попадает в аудит: в облаке событие `project.people_update` с тем, что было и что стало; локально вызов виден в журнале MCP.
- **`clone_cloud_project`** (только локальная Студия) скачивает проект облачной Студии, как кнопка «Открыть» у облачного проекта в списке. Передайте `url` проекта, например `https://studio.example.org/projects/<id>/`, или `project_id`, если сервер уже подключён (`server` нужен, только когда подключено несколько серверов). Студия использует сохранённый вход на сервер ([подключение](../start/local-from-cloud.md#подключение)), токен в аргументах не нужен и в ответ не попадает; адрес с логином или токеном отклоняется. Проект ложится в папку проектов из облака и остаётся связан с сервером. Скачивание идёт в фоне: инструмент ждёт до `wait_s` секунд (по умолчанию 45, меньше таймаута клиентов MCP), а если не дождался, повторный вызов с теми же аргументами подхватит ту же загрузку. Если проект уже на компьютере, он не скачивается заново.
- **`list_project_fields`** показывает поля проекта из описания шаблона, те же, что в настройках проекта: ключ, подпись, текущее значение, допустимые значения (`options`) или подсказку (`hint`, `example`), обязательность (`required_at`: `create` при создании, `finalize` к сдаче) и документы, где поле печатается (`printed_in`, по исходникам шаблона). В `set_with` указано, каким инструментом поле менять. В командном проекте у полей автора есть `author_values` по `slug`. В `unknown_meta` ключи метаданных, которых шаблон не описывает и не печатает (например группа, записанная в метаданные вместо карточки автора).
- **`set_project_meta`** задаёт поля (`entries`) и удаляет ключи (`unset`): удалённое поле снова берёт значение из шаблона. Пример: `{"entries": {"year": "2027"}, "unset": ["udc"]}`. Права те же, что в настройках проекта.
- **Обновление шаблона** идёт так же, как окно «Обновить шаблон» в настройках проекта.
    - `template_update_status` показывает версию шаблона проекта и доступные обновления: класс (`patch`, `minor`, `major`), что нового и что ломает, например `2026.1.1` и рекомендованное `2026.1.2`.
    - `plan_template_update` с `to_version` показывает, что станет с каждым файлом (`update`, `add`, `delete`, `merge`, `conflict`), и отдаёт `fingerprint`. Файлы проекта не меняются.
    - `apply_template_update` с `to_version` и `fingerprint` применяет ровно этот план; если проект за это время изменился, нужен новый план. Конфликты решает `resolutions` (`{"путь": "mine" | "theirs" | "markers"}`), по умолчанию файл остаётся вашим. Перед записью Студия делает снимок истории, отменить обновление можно в настройках проекта.
    - План и применение доступны тому, кто может управлять шаблоном проекта (владелец), и только в проекте, доступном для записи. В облаке применение попадает в аудит (`project.template_update`).

### Синхронизация с git-remote

**`git_sync`** делает то же, что кнопка синхронизации проекта: сохраняет снимок, забирает чужие изменения и отправляет свои. В локальной Студии это синхронизация с облачным сервером (проект из облака) или с подключённым репозиторием, в облаке с подключённым репозиторием. Инструмент ждёт итог до `wait_s` секунд (по умолчанию 45); если не дождался, ответ `status: running`, а повторный вызов присоединится к той же синхронизации, как и кнопка, нажатая во время идущей. В ответе `outcome` (`up_to_date`, `pushed`, `fast_forwarded`, `merged`, `conflicts`), число полученных и отправленных версий и файлы, слитые автоматически. При конфликтах ничего не отправляется и файлы на диске не меняются: в ответе список файлов с конфликтами, а решаются они в Студии кнопкой «Разобрать». Адрес репозитория и доступ к нему в ответ не попадают. Права те же, что у кнопки: нужна роль редактора, а в командном проекте ещё право править весь проект. Инструмент опасный, поэтому по умолчанию выключен.

### Документы: вариант

- **`set_document_variant`** выбирает вариант документа, как переключатель «Форматы документов» в настройках проекта: например, у презентации `pptx`, `beamer` или `reveal`. Передайте `doc_id` из `list_documents` и `variant`; без `variant` инструмент только покажет текущий вариант и допустимые для языка проекта. Неизвестный вариант отклоняется с перечнем допустимых. Смена сбрасывает статус документа в черновик, файлы прежнего варианта остаются. Права те же, что в интерфейсе: запись в документ, а проект должен быть доступен для записи. В облаке смена попадает в аудит событием `document.variant_update`.

Опасные инструменты (удаление проекта и файла, откат истории, синхронизация с git-remote) по умолчанию выключены: их включает поимённо администратор (облако) или вы сами (локально). Подписывать документы электронной подписью через MCP нельзя.

### Сборка

**`compile_document`** запускает сборку, как кнопка «Собрать». По умолчанию (`wait: true`) инструмент ждёт итог до 45 секунд: этого меньше, чем клиенты MCP ждут ответа. Если сборка идёт дольше (например, облачная сборка на личном раннере), ответ приходит без ошибки: `status: in_progress` и `compile_id`, а сборка продолжается. С `wait: false` инструмент сразу возвращает `compile_id`. Итог такой сборки показывает `get_compile` с этим `compile_id`, остановить её можно через `cancel_compile`.

## Безопасность

- Клиент действует от имени владельца токена: те же роли в проектах, квоты и лимиты, что в интерфейсе. Чужой проект для него не существует.
- Токену MCP достаточно права **MCP**; к обычному API он доступа не даёт. Отозвать токен можно там же, где он выпущен; он перестаёт действовать сразу.
- Вход по cookie браузера на `/mcp` не принимается.
- Каждый вызов попадает в журнал: инструмент, проект, исход и время, без содержимого аргументов. В облаке журнал на странице **Админка → MCP-сервер** и в общем аудите, локально в настройках MCP.
- Частота вызовов ограничена (по умолчанию 120 в минуту на человека); сборка, запись файлов и git считаются ещё и по своим лимитам.

## Для администратора

На странице **Админка → MCP-сервер**:

- общий переключатель MCP-сервера;
- группы и отдельные инструменты с переключателями; опасные включаются поимённо;
- группа **Администрирование** (пользователи, очередь, раннеры, аудит) выключена по умолчанию; даже включённой она доступна только администратору установки с токеном, где есть право **MCP: администрирование**;
- журнал вызовов.
