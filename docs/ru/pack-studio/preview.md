# Предпросмотр PDF и места подписей

<p class="hds-lede">Предпросмотр PDF собирает документ версии так, как его получит студент: на примере данных и при тех условиях, которые выбраны на экране («Для какого студента»). На собранном PDF можно поставить места подписей и метки даты мышкой.</p>

## Сборка

Предпросмотр открывается двумя путями: в «Содержимом» он стоит справа от документа (на узких экранах кнопкой **Предпросмотр PDF** в шапке документа, он выезжает шторкой), а на «Результате» его открывает кнопка **PDF** у документа в «Подробностях».

1. **Для какого студента**: условия берутся с экрана, у предпросмотра видно, какие из них изменены, и есть кнопка **Изменить условия**. Документ, которого при этих условиях нет в комплекте, предпросмотр не рисует, а предлагает «Сбросить условия» или «Показать при…».
2. **Пример данных**: файл примера или готовые наборы (ниже).
3. **Вариант документа**, если у документа есть варианты. Из некоторых вариантов PDF не собирается.
4. **Собрать PDF.** Сборка идёт так же, как у проектов: локально во встроенном Docker, на сервере на сборочных серверах установки в вашей квоте. Пока идёт сборка, видно «Собираю PDF…» и кнопку **Отменить**.

Рядом PDF (**Во весь экран**) и **Журнал сборки**. Та же сборка на тех же файлах второй раз не повторяется, PDF берётся из кэша. Если после сборки поменялись условия или файлы, Студия скажет об этом: **Собрать заново**. Одновременно идут не больше двух сборок у человека.

Первая сборка ждёт образ TeX. Если LaTeX упал, первая строка с «!» в журнале указывает место; предупреждения шаблона Jinja идут в журнал строками `[render]`. Если PDF у документа не бывает (презентации и подобные файлы), предпросмотр так и скажет.

## Примеры данных { #examples }

Готовые наборы есть всегда:

- **Обычный**: значения из подсказок и значений по умолчанию полей;
- **Длинные значения**: каждое строковое поле втрое длиннее, так видно переполнение строк титула;
- **Пустой**: только обязательные при создании поля, остальное печатается заглушками.

Свои примеры лежат в `templates/<шаблон>/examples/<имя>.yaml`, вне каталогов версий: их правка не меняет версию и не требует выпуска. Студия их не читает при создании проектов. Пример, который не читается, предпросмотр называет и просит выбрать другой.

```yaml
label: { ru: "Команда, руководитель из компании", en: "Team, company supervisor" }
name: { ru: "Контур согласования действий LLM-агента", en: "An Approval Gate for LLM Agents" }
lang: ru
staffing: team2
authors:
  - { name: "Иванов Иван Иванович", group: "МСПИН261" }
  - { name: "Петрова Анна Сергеевна", group: "МСПИН261" }
supervisor: { name: "Петров Пётр Петрович", position: "доцент", role: company }
meta:
  proposal_stage: "Предварительная"
```

- `lang`, `kind`, `staffing` пример предлагает как значения условий, их можно переключить.
- Люди: `authors` (до трёх), `supervisor`, `co_supervisor`, `academic_supervisor`; у человека `name`, `group`, `email`, `position`, `degree`, `role` (`university` или `company`).
- `meta`: значения полей анкеты по их ключам (строки, числа, `true` и `false`).
- Ответы анкет пример пока не задаёт.

## Места подписей { #places }

В «Содержимом» у документа страница **Подписи**: рамки подписей лежат на страницах PDF, справа список подписей документа. Всё сохраняется само.

- Перетащите рамку на нужное место страницы. Рамка показана в пропорции 3:1: в проекте высота зависит от картинки подписи.
- **Своё место документа** или **общее место** подписи (бледная рамка с пометкой «общее место»). **Сделать общим местом** делает место этого документа общим для всех документов без своего места, **Вернуть общее место** возвращает документу общее.
- Если в шаблоне есть строки подписи, подпись **следует за текстом**: встаёт на строку и двигается относительно неё, поэтому не собьётся, когда текст сдвинется. **Не следовать за текстом** оставляет её там, где она стоит сейчас. Если строк нет, подписи стоят на запасных местах, и их двигают сами.
- Метки даты: двигаются так же, **Поставить дату на строку** ставит метку на строку шаблона, **Убрать дату** убирает.
- Места округляются до миллиметра, ширина от 10 до 200 мм, рамка не выходит за лист. Точное место (страница, миллиметры от краёв) видно под «Подробности».

Правки мест пишутся в описание версии (`version.yaml`) точечно: остальной текст и комментарии файла не меняются. Места и метки даты не меняют состав документов и считаются небольшой правкой. У выпущенной версии места только для просмотра: рядом с замком кнопка **Править копию**. Как места устроены в описании версии: [Пак и шаблоны, заготовки подписания](../reference/pack.md).

Подсказки о местах (за краем листа, место `per_author` на общем документе, узкое место под плашку открепленной ЭП) приходят в «Замечания».

## Порядок подписания в этой ситуации { #route }

В разделе «Сроки и сдача» под каждой точкой видно, какой порядок подписания получит проект с людьми из условий на экране: кто подписывает по шагам, какие подписи шаблон добавил по условию (`signing_slots` с `when`) и какие при этих условиях не появятся, какие подписи необязательны, что автор проекта может добавить сам и какие пункты при этих условиях не сдаются. Считает это тот же код, что порядок в проекте. Условия общие с «Результатом» и предпросмотром: переключили научного руководителя на «Из компании» в одном месте, и порядок, и сборка видят это сразу.
