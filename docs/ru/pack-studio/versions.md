# Новая версия шаблона

<p class="hds-lede">Любая правка шаблона выходит новой версией: выпущенную не трогают. Мастер копирует базу в черновик, по ходу правок считает класс изменения (patch, minor, major), предлагает номер, собирает заметки к версии и выпускает её.</p>

Что значат классы и как проекты получают обновление: [Пак и шаблоны, версии](../reference/pack.md).

## Ход

1. **Новая версия** у шаблона в дереве (или **Новая версия от этой** над выпущенной версией). База по умолчанию последняя выпущенная версия, класс задаёт номер: patch `2026.1.3` даёт `2026.1.4`, minor даёт `2026.2.0`, major спрашивает год набора (`2027.1`). Каталог базы копируется в черновик со статусом `beta`, заметки пусты, блок `release` убран.
2. **Правки.** Полоса над редактором показывает класс черновика. **Причины класса** раскрывают список, клик ведёт в файл или манифест. Класс пересчитывается после каждого сохранения.
3. **Номер.** Если правки требуют больше, чем даёт номер (например, новое обязательное поле в patch-версии), полоса предупредит. **Номер** переносит черновик: мягче минимума выбрать нельзя, строже можно.
4. **Заметки.** Что изменилось для студентов и руководителей, ru и en парами, по пункту в строке. **Взять из отчёта** собирает черновик пунктов по найденным изменениям. «Что сломается» заполняется для удалений и ужесточений. Если номер мягче, чем предлагают мягкие правила (например, правка текстов, которую автор считает patch), напишите **Объяснение класса**: оно уйдёт в `release.note` и в описание PR. Перевод на английский пока пишется вручную.
5. **Выпустить.** Версия становится `stable`, получает дату и класс и попадает в реестр выпусков с дайджестом каталога. Галочка **Сделать версией по умолчанию для новых проектов** правит `default_version` шаблона. Без пунктов заметок ru и en линтер выпустить не даст.

В пространстве над git выпуск это правки рабочей ветки: версия выпущена в ветке, а выпущенной для всех станет после слияния PR (кнопка «Предложить изменения»). До слияния выпуск можно повторить: если после выпуска файлы менялись, полоса предложит **Выпустить заново**. В папке на диске выпуск сразу окончательный.

Если номер уже выпущен в основной ветке (кто-то успел раньше), Студия предложит следующий свободный номер и перенесёт туда правки.

## Перенести правки { #move }

Если каталог выпущенной версии правили мимо Студии (в дереве пометка «изменена»), над редактором кнопка **Перенести правки в новую версию**. Правки копируются в черновик следующего номера, в git каталог выпущенной версии возвращается к основной ветке. В папке на диске верните его сами (например, `git checkout`).

То же в командной строке: `hse-doc-studio pack new-version`, `pack classify`, `pack freeze`, см. [Командная строка и CI](ci.md).
