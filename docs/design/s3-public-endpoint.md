# Публичный адрес S3 и раннеры вне сети сервера

Находка на живом облаке (04.11.2026): человек подключил локальную Студию как личный раннер, и облачная сборка на нём падала с `PUT presigned url: ConnectError`. Сервер выдавал раннеру подписанную ссылку на внутренний адрес MinIO кластера, которого с ноутбука не видно. Тот же адрес получал бы и браузер при скачивании PDF по ссылке.

Решения ниже приняты по умолчанию; неочевидные помечены **Развилка**.

## 1. Кто и с какого адреса ходит в S3

| Участник | Куда | Через что | Адрес до изменений | Адрес после |
|---|---|---|---|---|
| api | все операции (запись, чтение, проверка, удаление, CORS бакета) | клиент boto3 с `HSE_STUDIO__S3__ENDPOINT` | внутренний | внутренний |
| раннер в сети сервера (под в кластере, контейнер compose) | выгрузка выхода сборки | PUT по ссылке из `POST /jobs/{id}/artifacts` | публичный, если задан `PUBLIC_ENDPOINT`, иначе внутренний | внутренний |
| раннер вне сети (личный, локальная Студия) | то же | то же | как у раннера в сети | публичный (`presigned`) или без ссылки, через api (`proxy`) |
| браузер и локальная Студия как клиент | PDF сборки и сдачи, `GET` с `Range` | редирект api на ссылку | публичный, если задан | публичный, если задан |
| раннер, исходники (блобы манифеста) | чтение | `GET /jobs/{id}/blobs/{sha256}` через api | api | api (в S3 раннер не ходит) |

Ссылки выдаёт ровно одно место: `S3ObjectStore._presign`. Раньше у хранилища был один подписывающий клиент: на публичный адрес, если он задан (настройка `public_endpoint` уже была, но ни чарт, ни compose, ни документация её не знали), иначе на внутренний. Получателя хранилище не различало, поэтому при заданном публичном адресе раннер в кластере выходил наружу и возвращался обратно.

Выходы сборки раннер заливает ссылками, исходники берёт у api. Поэтому единственный путь раннера в S3 это выгрузка результата.

## 2. Что сделано

- **Адрес по получателю.** `LinkAudience` (`internal` или `outside`) в `presign_get` и `presign_put` порта `IObjectStore` (и `IBlobStore`). `internal` подписывается клиентом с внутренним адресом, `outside` клиентом с публичным (без публичного адреса тоже внутренним: поведение до изменений). По умолчанию `outside`: все прежние вызовы (браузер, PDF сдачи) остались прежними.
- **Подпись сразу для публичного хоста.** Подпись S3 v4 включает заголовок `Host`, поэтому подмена хоста в готовой ссылке даёт 403. Для публичного адреса создан отдельный клиент boto3 с `endpoint_url=public_endpoint`, он и подписывает. Это проверяет интеграционный тест на MinIO: ссылка, подписанная для второго имени сервера, работает, а та же ссылка с подменой хоста строкой нет.
- **Кто «внешний».** `RunnerStoragePolicy` (`core/jobs/storage.py`): раннер с областью `personal` внешний; общий раннер внутренний. **Развилка:** сервер не может надёжно определить сеть раннера сам (NAT, прокси, исходящие адреса кластера), поэтому правило по владельцу: личные раннеры это ноутбуки, общие ставит админ рядом с сервером. Исключение (общий раннер на другой ВМ) задаётся `HSE_STUDIO__S3__SHARED_RUNNERS_OUTSIDE=true`. Определять по IP (`last_seen_ip`) отвергнуто: за ingress и NAT он не говорит, по какую сторону сети раннер.
- **Выбор в протоколе раннера.** `RunnerJobIoService` берёт область раннера из `runner.scope` и передаёт получателя в `IJobBlobStore.url_for` и `IJobOutputIngest.announce`. Протокол раннера не менялся: раннеру безразлично, какой адрес в ссылке.
- **Настройки.** `HSE_STUDIO__S3__PUBLIC_ENDPOINT` (теперь с проверкой: схема, хост, порт, без пути и логина), `HSE_STUDIO__S3__OUTSIDE_RUNNER_ACCESS` (`presigned` по умолчанию или `proxy`), `HSE_STUDIO__S3__SHARED_RUNNERS_OUTSIDE`. Helm: `s3.publicEndpoint`, `s3.outsideRunnerAccess`, `s3.sharedRunnersOutside`, `s3.corsOrigins`; compose: `S3_PUBLIC_ENDPOINT`, `S3_OUTSIDE_RUNNER_ACCESS`.
- **Понятная ошибка.** Если публичного адреса нет и внутренний с машины раннера не открывается, раннер получает `httpx.ConnectError`/`ConnectTimeout` на PUT. Раньше это было `RunnerUnreachable("PUT presigned url: ConnectError")`, и сборка заканчивалась `artifact_upload_failed`. Теперь `StorageUnreachable`: сообщение называет схему, хост и порт хранилища (подпись из query в текст не попадает) и две настройки, которые чинят (`PUBLIC_ENDPOINT` и `OUTSIDE_RUNNER_ACCESS=proxy`), код ошибки сборки `storage_unreachable`. Прочие ошибки PUT (обрыв посреди передачи, 4xx) остались прежними: это не про маршрут.
- **Самодиагностика.** Проверка «Объектное хранилище» после успешного круга записи и чтения предупреждает (`warn`, причина `object_not_public`), если выполнены три условия: S3 с собственным `endpoint` (не AWS по региону), публичного адреса нет, режим не `proxy`, и при этом есть неотозванные раннеры вне сети (личные, а с `SHARED_RUNNERS_OUTSIDE` и общие). Подсказка называет настройки и раздел документации. Сбой хранилища приоритетнее предупреждения.

## 3. Проксирование: решение

**Развилка: режим `proxy` включён в этот срез.** Оценка до реализации показала, что основа уже есть в протоколе раннера: если `POST /jobs/{id}/artifacts` вернул `url: null`, раннер сам делает `PUT /jobs/{id}/artifacts/{sha256}` через api. Этот путь уже проверяет токены раннера и задачи, сверяет размер с заявкой (заявка не больше `jobs.max_artifact_bytes`, по умолчанию 512 МиБ), считает sha256 и пишет в S3 только совпавшее. Отдельного эндпоинта, нового кода передачи и изменений раннера не требуется: режим сводится к решению «не выдавать ссылку» (`audience=None`).

Риски, которые остаются и описаны в документации админа:

- Нагрузка на api: весь трафик результатов внешних раннеров идёт через процесс api. Результат сборки это PDF и вложения, обычно единицы мегабайт, но предел 512 МиБ на выход.
- Диск: тело принимается во временный файл (`SpooledTemporaryFile`, 8 МиБ в памяти), нужен запас на число одновременных выгрузок умноженное на размер.
- Ingress перед api должен пропускать большие тела и долгие запросы.
- Режим касается только раннеров. Браузерам PDF по ссылке по-прежнему нужен публичный адрес.

Режим выключен по умолчанию: публичный адрес дешевле для api и это штатный путь; `proxy` для установок, где публиковать хранилище нельзя.

## 4. Что не вошло

- Скачивание PDF в браузере без публичного адреса S3 (стриминг через api вместо редиректа). Сейчас без публичного адреса редирект ведёт на внутренний адрес. Диагностика предупреждает только о раннерах; предупреждение для браузеров можно добавить, но признак «кто-то качает PDF» в базе не хранится.
- Учёт трафика proxy по человеку и квота на объём выгрузок.
- Автоматическое определение, что раннер вне сети (раннер мог бы сам сообщить об этом при `/announce`, сервер сверил бы ответ пробной ссылкой). Нужно только если правило «личный = внешний» окажется грубым.
- Возобновляемая выгрузка больших выходов; сегодня PUT целиком, повтор с начала.
- Сам маршрут к MinIO на проде и кластерные объекты: это настройка установки, в репозиторий не входит (примеры в `docs/ru/deploy/runners.md`).

## 5. Тесты

Юнит: правило получателя (`RunnerStoragePolicy`), выбор адреса в `RunnerJobIoService` для общего, личного, proxy и объявленного внешним общего раннера; адрес и отсутствие ссылки в `AnnouncedJobOutputIngest`; приём выхода через api в режиме proxy и отказ при превышении заявленного размера; проверка и нормализация `public_endpoint`; фабрика хранилища; ошибка раннера `StorageUnreachable` без секретов подписи на уровне клиента и сборки в цикле раннера (код `storage_unreachable`); правило диагностики. Интеграция: подпись для внутреннего и публичного хоста в moto и в настоящем MinIO (работающая ссылка на публичное имя, провал при подмене хоста, PUT по ссылке); проба диагностики на Postgres. Чарт: `helm lint`, golden-рендер с `ci/values-public-s3.yaml`, отсутствие переменных по умолчанию, схема отвергает публичный адрес с путём.
