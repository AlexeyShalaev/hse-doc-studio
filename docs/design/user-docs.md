# Пользовательская справка: сайт, съёмка медиа, контекстная помощь

Статус: реализовано в ветке `feat/user-docs` (03.11.2026). Образец: справка Yahad
(`attendance-manager/services/user-docs`, `tools/docs-studio`, `widgets/help`).

Справка отвечает на вопрос «как пользоваться», инженерная документация в `docs/` (Zensical,
GitHub Pages) отвечает на «как устроено и как развернуть». Это два разных сайта для разных
читателей; `docs/` и `docs.yml` не менялись.

## 1. Что сделано

| Часть | Где |
|---|---|
| Сайт справки ru/en, 16 статей (11 пользователя, 5 администратора) | `services/user-docs` |
| Раздача по `/help/` тем же процессом, выбор сборки по сессии | `services/api/hse_doc_studio/api/help_site.py` |
| Справка в образе (офлайн в локальной версии) | `deploy/all-in-one/Dockerfile`, стадия `help-builder` |
| Панель справки, книжка в шапке, `?`, ⌘K, значки «?» у полей | `entities/help`, `features/help-center` |
| Стенды и съёмка скриншотов и роликов | `tools/docs-studio` |
| Проверки в CI, ручная/недельная съёмка | `ci.yml` (джоб `user-docs`), `user-docs-media.yml` |
| Скилл для агентов | `.claude/skills/docs-add-runbook` |

## 2. Решения

| № | Решение | Почему |
|---|---|---|
| D1 | Отдельный сайт на Astro Starlight, а не второй сайт Zensical. | Шаги статьи живут во frontmatter и уходят приложению JSON-ом (`help-map.json`, `help/<ключ>.json`): у Astro это типизированная коллекция и эндпоинты сборки, у Zensical понадобился бы отдельный генератор поверх Markdown. Нужны свои компоненты (кадры под тему, ролик), подмена темы под ключ приложения, сборка по аудиториям с вырезанием статей до индексации и офлайн-поиск (Pagefind встроен). Это ровно то, что уже работает в Yahad; перенос дешевле изобретения. Zensical остаётся для `docs/`, его сборка и публикация не тронуты. |
| D2 | Путь `/help/` на хосте Студии, раздаёт бэкенд Студии (FastAPI), а не nginx или поддомен. | У Студии один процесс и один порт в обоих режимах. Один origin: нет CORS и правок CSP, общий `localStorage` (тема справки = тема приложения), cookie сессии видна справке. В локальной версии справка лежит в образе и работает без сети. |
| D3 | Две сборки: `user` (без статей администратора) и `admin` (все). Медиа общие, `dist/media`. | Спрятать ссылки мало: страница осталась бы по адресу, а её текст в индексе поиска. Вырезание до сборки убирает статью из навигации, поиска и адресов. Кадры админки не секрет, а копия медиа на аудиторию удвоила бы образ. |
| D4 | Сборку `admin` получает админ установки (`is_instance_admin`) и только там, где ему открыта админка по host/IP; все остальные, включая не вошедших и локальную Студию, получают `user`. | Тот же критерий, что у `capabilities.admin`. У локальной Студии нет админки установки, её «администрирование» (обновления, Docker) описано в статьях пользователя. |
| D5 | Справка пользователя открыта без входа. | Это та же информация, что в публичном репозитории и на сайте документации; на экране входа справка тоже нужна (статья «Начало работы»). |
| D6 | Приложение не знает ключей статей: экран находит статью по `help.routes` (шаблоны путей react-router, можно с `?tab=`), карта публикуется сборкой справки. | Справку экрану добавляют правкой статьи, без правки фронтенда. Ранжирование: совпавшая вкладка, затем статья, у которой маршрут первый, затем порядок карты. |
| D7 | Панель — отдельный lazy-чанк; карта и статья грузятся только после первого открытия. В основной бандл входят кнопка, стор, значок «?» и словарь `help` (~1 КБ). | Требование «без раздувания бандла». |
| D8 | Шаги рисуются из данных своим мини-рендерером (жирный, курсив, код, ссылки) в React-узлы. | Справка не вставляет HTML в приложение; ссылки на `javascript:` остаются текстом. |
| D9 | Медиа генерируются сценарием со стенда, не снимаются руками; кадр шага `<ключ>/step-NN.<ru|en>.<light|dark>.webp` (1600 px, WebP q80), ролик `<ключ>/clip.<lang>.<theme>.{webm,mp4}` 1280 px 24 fps + постер WebP. | Снятое руками устаревает и больше не переснимается. WebP поддерживают все целевые браузеры; AVIF дал бы ещё ~20%, но вдвое больше файлов в репозитории ради `<picture>`. WebM (VP9) идёт первым, MP4 (H.264) для старого Safari. Подписей в кадре нет: слова живут в шагах. |
| D10 | Захват ролика через CDP-скринкаст с реальными отметками времени, а не `recordVideo`. | VP8 Playwright мылит текст; кадры скринкаста резкие, паузы загрузок сжимаются. |
| D11 | Два стенда: локальная Студия на изолированном каталоге данных (:17790, засеянные ВКР ru/en) и существующий server-lite (:8110, админ и три пользователя). | Локальный режим нужен для редактора, сборки и проверок (Docker и TeX Live на машине), серверный для совместной работы и админки. Сид идёт через API и идемпотентен. |
| D12 | Медиа хранится в git (`services/user-docs/public/media`). Съёмка в CI ручная и раз в неделю, не required; результат приходит артефактом. | Съёмка долгая и зависит от Docker и TeX Live; сборка справки не должна зависеть от съёмки (недостающий кадр в панели и на сайте просто не показывается). |
| D13 | Устаревание видно: у статьи `verified.at`/`sources`, сайт пишет «Проверено … на версии …». CI сверяет маршруты, существование `sources`, пары ru/en (число шагов, кадры, ролик, маршруты) и битые ссылки в обеих сборках. | Инструкция с исчезнувшей кнопкой хуже отсутствующей. |
| D14 | Онбординг (ветка `feat/onboarding`) и экран «Локальная версия» (`feat/local-from-cloud`) делают свои ветки; справка на них только ссылается. | Не пересекаться зонами. Когда онбординг с демо-сценарием появится в `next`, его фронтовые моки можно использовать в сценариях съёмки вместо стенда. |

## 3. Как пересобрать медиа

```sh
make docs-media                                   # всё: интерфейс, справка, оба стенда, съёмка
make docs-media SCENARIO="runbooks/create-project admin/runners"
make docs-stand-local && LANGS=ru THEMES=dark make docs-record SCENARIO=runbooks/build
CHECK_MEDIA=1 node services/user-docs/scripts/check.mjs   # все кадры и ролики на месте
```

Требования: Docker запущен (TeX Live для локальной сборки, server-lite), `uv`, Node 24 + pnpm,
ffmpeg с libx264 и libvpx-vp9.

## 4. Решения на подтверждение

1. **Справка пользователя без входа на сервере** (D5). Альтернатива: только вошедшим, как в Yahad.
2. **Медиа в git, а не Git LFS/релизный ассет** (D12). Полный комплект: ~16 статей × 2–3 кадра ×
   4 варианта плюс 7 роликов × 4 варианта × 2 формата; ориентир 20–40 МБ, каждая пересъёмка
   добавляет столько же в историю. Если это много: LFS для `public/media` или ролики только ru/en
   в одной (тёмной) теме.
3. **Ролики в двух форматах** (WebM + MP4). Можно оставить только MP4 (H.264) и вдвое сократить объём.
4. **Справка администратора по тому же критерию, что админка** (D4): админ, зашедший с
   неразрешённого host/IP, читает сборку пользователя.
5. **Где показывать справку на экранах без шапки** (вход, мастер первого запуска): сейчас только
   через `/help/` и ссылку в статье «Начало работы»; кнопку на экране входа можно добавить.
6. **Недельная автосъёмка** (cron в `user-docs-media.yml`): оставить, или только вручную.
7. **Маршрут экрана «Локальная версия»** добавить в `help.routes` статьи `runbooks/local-version`
   после слияния `feat/local-from-cloud`.

## 5. Что не сделано

- Поиск в панели приложения ищет по названию и описанию статей (каталог из карты). Полнотекстовый
  поиск есть на сайте (Pagefind); серверного поиска и ответов ИИ по справке, как в Yahad, нет.
- Главы ролика (`chapters`) рекордер считает, но во frontmatter не записывает.
- Часть кадров показывает ближайший воспроизводимый экран, а не итог шага: на стендах нет
  удалённого git-репозитория (подключение, конфликты), кода устройства (вход локальной Студии в
  облачную), ключа модели (ответ агента) и ошибки сборки. Для этого нужны засеянный git-remote и
  фейковый провайдер ИИ на стенде (как `e2e/fake_openai`), это следующий шаг.
- Экран «Локальная версия» (`feat/local-from-cloud`) ещё не в `next`: его маршрут и кадр
  добавляются в `runbooks/local-version` после слияния.
- Кадры содержат путь `~/Documents/hse-studio-docs` с именем пользователя машины, где снимали;
  `DOCS_PROJECTS_HOME` позволяет снять в нейтральном каталоге.
