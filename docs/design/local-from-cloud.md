# Локальная Студия из облака

Статус: реализовано в ветке `feat/local-from-cloud` (03.11.2026), решения из раздела 6 ждут подтверждения; раздел 7 («Облако в списке проектов») реализован в ветке `feat/local-cloud-projects` (03.11.2026) и заменяет пункт 6 раздела 2 и «Вне объёма» про выбор проекта списком. Основа: `collaboration.md` (раздел 12 «Гибрид: сервер как remote») и `local-sync.md` (автосинхронизация и выгрузка PDF).

## 1. Проблема

Всё нужное для работы локально с облачным проектом уже было: установщики (`deploy/install.sh`, `install.ps1`), вход локальной Студии на сервер кодом устройства, клонирование с сервера, автосинхронизация, выгрузка PDF. Но из облака к этому не было дороги: человек на `https://hse-doc-studio.ai-ops.ru` не знал, что есть локальная версия, как её поставить и как связать с этим сервером.

## 2. Путь пользователя

1. В облаке: меню аккаунта → «Локальная версия» (или пустой список проектов, настройки проекта «Синхронизация → Клонировать с сервера», подсказка «облачная сборка недоступна»). Открывается `/local-studio`.
2. Экран объясняет, зачем (сборка у себя, офлайн, скорость), что нужно (Docker, диск, память), и даёт команду установки для своей ОС. Адрес сервера в команде уже подставлен (`HSE_STUDIO_CONNECT`), кнопка копирует её.
3. Скрипт ставит Студию и открывает в браузере `http://localhost:17240/connect?server=<облако>`. Если Студия уже стоит, ту же страницу открывает кнопка «Подключить локальную Студию».
4. Локальная Студия проверяет сервер (`GET /git/servers/check`): что это Студия, её версия против своей, есть ли уже вход. Показывает карточку сервера и, при расхождении версий, предупреждение.
5. Кнопка «Подключиться к <host>» запускает существующий вход кодом устройства: код на экране, ссылка открывает `/device?code=…` на сервере, человек жмёт «Разрешить».
6. Для проекта (`/local-studio?project=<id>` → «Открыть в локальной Студии» → `/connect?server=…&project=<id>`): если проект уже есть локально, он открывается; иначе Студия сама скачивает его в папку проектов (раздел 7). Автосинк и выгрузка PDF включаются сами (вход по коду устройства, `local-sync.md` A2 и P7).

## 3. Решения

| № | Решение | Почему |
|---|---|---|
| L1 | Диплинк это обычная ссылка `http://localhost:<порт>/connect?server=…&project=…`, а не свой протокол (`hse-studio://`). | Локальная Студия и так веб-приложение на localhost; свой протокол потребовал бы регистрации обработчика в ОС, а у контейнера её нет. Переход по ссылке из https на http://localhost браузеры разрешают. |
| L2 | Облако не опрашивает локальную Студию (нет запросов из браузера к localhost). Порт по умолчанию 17240, человек может поправить его на экране, значение хранится в `localStorage`. | Запрос из https-страницы к localhost упирается в Private Network Access и CORS, а ответ ещё и раскрывал бы сайту, что стоит на компьютере. Ссылка работает без этого. |
| L3 | Вход начинается только по нажатию «Подключиться к <host>» на экране локальной Студии, адрес сервера показан крупно. | Любой сайт может открыть ссылку на `/connect?server=…`; автозапуск входа помог бы фишинговому серверу. Один щелчок с видимым адресом остаётся «в один клик». |
| L4 | Новое на сервере: `GET /api/v1/local-studio` (вошедший пользователь): внешний адрес (`auth.public_url`, без него адрес запроса), версия, включён ли git, рекомендуемый тег образа, ссылки на скрипты и релизы из `github_repo`. | Адрес в командах и диплинке должен совпадать с адресами клонирования (`public_url`), а не с тем, как человек открыл сайт. |
| L5 | Новое в локальной Студии: `GET /api/v1/git/servers/check?url=` (только локально): версия сервера по `/git/-/info`, совместимость, рабочий вход на этот хост и порт, если есть. Вход и клонирование не менялись, переиспользуются `/git/servers/login` и мастер клонирования (`/wizard?mode=clone&url=…&credential=…`). | Минимум нового кода; одна проверка отвечает и на «доступен ли сервер», и на «уже подключены», и на «совместимы ли версии». |
| L6 | Совместимость по `MAJOR.MINOR` (`core/git_remote/local_studio.py`): равные версии или разный PATCH это «совместимо», иначе «локальная старше» или «локальная новее», непонятная версия это «неизвестно». Расхождение только предупреждает, не блокирует. | Внутри одной линии формат проекта и протокол `/git/-/*` не ломаются; несовместимые данные и так ловят `read_compat` и `write_compat` проекта при синхронизации. |
| L7 | Установщики понимают `HSE_STUDIO_CONNECT=<адрес>`: после запуска открывают `/connect?server=<адрес>` вместо главной. Пропускается только `https://host[:port]` (и `http://localhost`), строка уходит в браузер без кодирования. Мастер первого запуска перезагружает ту же страницу, поэтому намерение подключиться переживает перезапуск контейнера. | Одна команда из облака ставит Студию и сразу ведёт к подключению. Старые скрипты переменную просто игнорируют. |
| L8 | Команды по умолчанию ставят `latest`; галочка «ту же версию, что у сервера» добавляет `TAG=<MAJOR.MINOR>` (тег образа публикуется в GHCR вместе с релизом). | Сервер обычно не старше последнего релиза; закреплять тег по умолчанию значило бы отключить обновления. |
| L9 | Стабильные адреса и экспорт для других веток: `LOCAL_STUDIO_PATH` (`/local-studio`), `localStudioPath(projectId)`, `CONNECT_SERVER_PATH` (`/connect`), компонент `LocalStudioLink` (`@entities/local-studio`), кнопка `OpenInLocalStudio` (`@features/local-studio-guide`). В локальной Студии `/local-studio` ведёт на `/connect`, на сервере `/connect` ведёт на `/local-studio`. | Справка, онбординг и подсказка «облачная сборка недоступна» ссылаются на экран, не зная, в каком режиме открыты. |
| L10 | Оба экрана грузятся лениво (свои чанки), словарь `localStudio` общий. | Основной бандл не растёт на экраны, которые открывают редко. |

## 4. Точки входа

- Облако: меню аккаунта «Локальная версия»; пустой список проектов; «Настройки проекта → Синхронизация → Клонировать с сервера», вкладка «Студия на компьютере» (кнопка «Открыть в локальной Студии»); подсказка «облачная сборка недоступна» (ветка `fix/no-runners-honest` ставит `LocalStudioLink`).
- Локальная Студия: кнопка «Подключиться к серверу» на главной и в пустом списке проектов; `/connect`.

## 5. Вне объёма

- Проверка, запущена ли локальная Студия, из облака (см. L2).
- Установщик-приложение (dmg, msi): Студия по-прежнему контейнер.
- Подключение нескольких серверов одной кнопкой.

## 6. Решения на подтверждение

1. **Порт и проверка (L2).** Облако не пытается найти локальную Студию само; если скрипт занял не 17240, человек вводит порт на экране. Альтернатива: опрос `http://localhost:17240..17250/health` из браузера (нужны CORS и согласие Private Network Access).
2. **Один щелчок вместо автоподключения (L3).** Ссылка из облака не начинает вход сама.
3. **Тег по умолчанию `latest` (L8)** и галочка закрепления версии сервера. Пока релиз 0.3.0 не выпущен (релизный PR на паузе), `latest` это 0.2.x, где экрана `/connect` ещё нет: до релиза путь из облака работает только с образом из `next`.
4. **Предупреждение, а не запрет (L6)** при разных `MAJOR.MINOR`.
5. **`HSE_STUDIO_CONNECT` в скриптах (L7)** читается с ветки `master` (`raw.githubusercontent.com/.../master/deploy`): до слияния в `master` установщик откроет главную, а не экран подключения.
6. **Адрес документации** на экране: `https://alexeyshalaev.github.io/hse-doc-studio/start/local-from-cloud/`; страницу может переписать ветка `feat/user-docs`, адрес нужно сохранить.

## 7. Облако в списке проектов

Проблема (живое использование 03.11.2026): после «Продолжить» на экране подключения открывался мастер «Клонировать проект из git». Проект уже в облаке, слово git человеку ни к чему, а PDF в итоге собирали в отдельном локальном проекте, не связанном с облаком. Решения владельца:

| № | Решение | Почему |
|---|---|---|
| C1 | Список проектов локальной Студии сам показывает проекты человека на серверах, куда Студия вошла (`GET /git/cloud/projects`, только локально). Карточки с пометкой «Облако»: «Не открыт на этом компьютере» с кнопкой «Открыть» и обычная карточка проекта с пометкой «Облако» там, где проект уже открыт. | Человек видит свои проекты сразу и не думает о git. |
| C2 | Список берётся у сервера по уже сохранённому входу (`/git/-/projects`), чужих проектов в нём нет по построению: тот же отбор, что и у клонирования (источники по членству, группе или организации, ссылочные права не считаются). Нового эндпоинта сервера и новых прав нет. | Одна граница доступа, а не вторая рядом. |
| C3 | Сопоставление по идентификатору проекта на сервере: у клона он совпадает с идентификатором локального проекта (`project.json`). Открытый локально проект не дублируется, на его карточке пометка «Облако». Бэкенд ставит `is_local`, фронтенд дополнительно сверяет со своим списком, поэтому карточка пропадает сразу после скачивания. Один проект на двух серверах показывается один раз. | Проект связан с сервером своим идентификатором, а не папкой. |
| C4 | Сбой сервера приходит состоянием сервера в ответе, а не ошибкой запроса: `ok`, `expired` (срок доступа вышел, запрос не делается), `revoked` (сервер отказал, доступ помечается как отказавший), `unreachable`. Над списком строка: «Войти заново» или «Повторить»; локальные проекты остаются. Несколько входов на один адрес сворачиваются в один сервер: самый новый рабочий, иначе отказ самого нового. Пустой сервер: короткая пометка, обрезанный (больше 500): сколько показано. | Один недоступный сервер не должен прятать остальное. |
| C5 | Открытие: `POST /git/servers/{вход}/projects/{id}/open`. Проект уже открыт: ответ без операции. Иначе проект ищется среди тех, что сервер отдаёт этому входу (чужого или несуществующего нет: 404), берётся свободная папка в стандартной папке проектов по названию (`GetCloneDefaultsUC`) и запускается обычное клонирование с адресом `<сервер>/git/<id>.git` и этим входом. Повторное нажатие, пока идёт скачивание, подхватывает ту же операцию. Прогресс, отмена и итог те же, что у клонирования. Нет профиля автора (`profile_required`): окно «Представьтесь» на месте, затем повтор. | Одно нажатие вместо мастера; клонирование не переписывалось. |
| C6 | Стандартная папка проектов меняется настройкой `projects_dir` («Настройки → Доступ к репозиториям → Папка для проектов из облака»). Это путь на компьютере человека; он обязан лежать в папках, к которым у Студии есть доступ (иначе 400), пустое значение возвращает стандартную. Настройка машинная: в файл переноса настроек не выгружается и из него не загружается. Она же задаёт папку по умолчанию в мастере клонирования. | Папка не выбирается каждый раз, но не навязана. |
| C7 | `/connect?…&project=<id>` после «Продолжить» открывает указанный проект (есть: открывает, нет: скачивает с прогрессом и открывает). Без `project` «Продолжить» ведёт в список проектов. Мастер клонирования с выбором папки и адреса остаётся как расширенный путь (кнопка «Клонировать из git» на экране проектов, источник «Сервер HSE Doc Studio»), но с экрана подключения на него больше не ведут. | Путь «облако Студии» не знает слова git. |
| C8 | В панели сборки локального проекта, не подключённого к серверу, когда Студия вошла на сервер (есть рабочий вход, `pdf_upload.available = false`): «Проект не подключён к облаку, PDF останется на этом компьютере» и ссылка на документацию. Кнопки «Подключить к облаку» нет: сервер принимает только проекты, созданные на нём (push не создаёт проект), и переноса проекта на сервер одним действием в продукте нет. | Не обещаем действие, которого нет. |

Вне объёма: перенос локального проекта в облако, выбор сервера при нескольких входах (проект открывается с того сервера, на котором он найден), показ проектов, к которым есть только ссылочный доступ (клонирование их не отдаёт).
