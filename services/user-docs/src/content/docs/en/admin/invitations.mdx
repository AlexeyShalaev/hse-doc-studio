New people get onto the server through an administrator invitation, through self-registration
(if the mode allows it) or through single sign-on. An invitation is the most reliable way: it
works with and without mail, and a person who comes by the link does not wait for approval.

<Steps />

## If something goes wrong

- **The window was closed before the link was copied, or the link got lost**: find the invitation
  in the table and choose **Issue a new link**. The previous link stops working.
- **“The invitation is no longer valid”**: it expired or was revoked. Issue a new link or create
  the invitation again.
- **The person sees “This installation has no mail configured…”**: self-registration without SMTP
  is closed. Send them an invitation, or configure **Mail (SMTP)** in **Sign-in and registration**
  and check it with **Send** in the **Test email** block.
- **The invitation email did not arrive**: find it by address in the **Mail** section. It shows
  whether the email went out and what the SMTP server replied ([Mail](/help/en/admin/mail/)). You
  can also pass the link without email: **Issue a new link**.
- **The person registered but cannot sign in**: their request waits on the **Approvals** tab.
  Approve it and sign-in opens.
- **An address from “No approval for addresses” still landed in the queue**: mail is not
  configured on the server, or the rule was removed before the person opened the link from the
  email. The decision is made when the email is confirmed, by the current list. Check the address
  with **Check an address** and approve the request by hand.
