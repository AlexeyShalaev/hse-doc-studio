Server updates need no manual commands: a separate updater service takes a database snapshot,
pulls and verifies the image, applies migrations, restarts the services and waits for the new
version to answer. If something does not come up, it brings back the previous images and, when
needed, the database.

<Steps />

## If something goes wrong

- **“The updater service does not answer”**: the update buttons do not work until it runs. Run
  `docker compose up -d updater` on the server. Release checks and notifications still work.
- **“The update executor is not connected”**: this is the case with Helm and with compose without
  the updater profile. Install with the command from the **Version** block or enable the service:
  `docker compose --profile updater up -d` with UPDATER_TOKEN in .env.
- **Outcome “Needs hands”**: the update failed and the rollback did not finish. Open **Log**: it
  shows where the database snapshot is and the command to bring the services back.
- **“This release publishes no image digest”**: a verified update will not pass. Wait for the next
  release or pick **None** in **Image verification** if you trust the source.
- **“Rollback refused: that version needs a different database schema”**: the version you want runs on a different database schema than the current one. Nothing was done and the data is untouched. Restore a backup taken on that version by hand.
- **“The rollback did not come up”**: the system has already gone back to the version you rolled back from. The reason is in **Log**; you can return to the version you left with the button in the banner or with an update.
