A backup captures the whole installation: the database, project files, object storage and
settings. The parts are encrypted on the server and stored in the destination you choose, S3 or a
directory. A copy on the same disk as the data does not survive losing that disk, so keep the
destination on another volume, host or provider.

## If something goes wrong

- **“The last backup (…) failed”**: open **Run history**, the **Result** column shows the reason.
  Fix it and click **Back up now**: failed runs are not retried automatically.
- **Warning “This is the same storage or volume as the primary one…”**: losing it takes both the
  data and the backups. Add a destination on separate storage.
- **“Saved keys cannot be decrypted (SECRETS_KEY does not match) or the passphrase is not set”**:
  the server runs with a different SECRETS_KEY, or the passphrase is empty in **Passphrase** mode.
  Put the previous key back into the environment or enter the passphrase in **Schedule and
  retention**.
- **“The write stopped midway”**: the database is restored in one transaction, but files and
  objects may be incomplete. Click **Retry the write**; if the app restarted during the write,
  finish the restore with the CLI command shown for the backup.
