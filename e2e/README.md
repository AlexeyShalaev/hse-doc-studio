# Приёмочные e2e на стенде server-lite

Playwright проходит сценарии M1 по настоящему стенду (образ приложения в режиме server и Postgres в compose), а не по демо-миру фронта. Что проверяется, на ru и en:

- аноним попадает на экран входа, неверный пароль отклоняется;
- после входа видны только свои проекты (три демо-пользователя из seed);
- проект создаётся мастером (11 шагов) и остаётся в списке после перезагрузки;
- второй пользователь не видит чужой проект ни в списке, ни по прямой ссылке, ни через API;
- выход закрывает сессию.

Язык интерфейса задаёт локаль браузера, поэтому каждый сценарий идёт дважды. Скриншоты каждого шага лежат в `screenshots/ru` и `screenshots/en`, в CI это артефакт `e2e-screenshots`.

## Запуск

Из корня репозитория:

```bash
make server-lite-up server-lite-seed   # стенд и демо-данные
make e2e-install                       # один раз: зависимости и Chromium
make e2e-m1                            # сценарии
```

Вместо загрузки Chromium можно взять установленный Chrome: `make e2e-m1 E2E_CHANNEL=chrome`.

Против любого другого стенда: `E2E_BASE_URL=http://localhost:8100 E2E_SEED_PASSWORD=... pnpm test` из этого каталога. Пароль это `SERVER_LITE_SEED_PASSWORD` из `scripts/dev/server-lite/.env`.

Сценарии создают проекты `E2E проект ru` и `E2E проект en`: на чистом стенде они единственные новые, при повторном прогоне появляются дубли названий, список от этого не ломается. Чистый стенд: `make server-lite-reset`, затем up и seed.

## Полный смоук на стенде deploy/server

`tests/full.spec.ts` (проект Playwright `full`) идёт по полному серверному набору: api, раннер, Postgres и MinIO. Сценарии по порядку на одной базе:

- мастер первого запуска создаёт администратора и открывает регистрацию, повторно мастер не пускает;
- регистрация без SMTP: нейтральный ответ, ссылка подтверждения, вход;
- изоляция: чужой проект не виден в списке, по ссылке и через API, `/api/admin` не-админу отвечает 404;
- сборка через раннер, PDF отдаётся владельцу временной ссылкой на хранилище, чужому 404;
- квота один запуск на пользователя и справедливая очередь: 15 сборок одного пользователя не задерживают сборку другого;
- раннер убит посреди сборки, сборка заканчивается после его возвращения;
- рестарт api посреди сборки: сессия жива, запись доведена до конца;
- админка, раннеры, на ru и en.

```bash
make server-stack-build server-stack-up   # образ с extra server и стенд на 127.0.0.1:17251
make e2e-install                          # один раз
make e2e-full                             # сценарии, скриншоты в screenshots/{ru,en}/full-*.png
make server-stack-down                    # стереть стенд
```

Сборка тянет образ TeX Live (несколько гигабайт) при первом прогоне. В CI то же делает джоб `server-stack-smoke` в deploy-smoke. Пока сервер-режим не включён финальным срезом, стенд стартует с флагом experimental из `deploy/server/compose.smoke.yml`.

Очередь на настоящем Postgres дополнительно проверяет soak `services/api/tests/integration/e2e/test_queue_soak_pg.py`: 200 задач, случайные сбои раннеров, ни дублей закрытия, ни потерянных задач.
