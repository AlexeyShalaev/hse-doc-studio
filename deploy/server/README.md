# Общий сервер HSE Doc Studio (docker compose)

Развёртывание серверного режима на одной машине: api, раннер задач, Postgres, MinIO (S3) и по желанию
два LanguageTool, ONLYOFFICE и Ollama. Локальная установка для одного пользователя живёт отдельно
в `deploy/all-in-one`.

## Состав

| Сервис | Назначение | Профиль |
|---|---|---|
| `api` | веб-интерфейс и API, режим `server`, миграции базы на старте | всегда |
| `runner` | берёт задачи у api, собирает документы в соседних контейнерах | всегда |
| `postgres` | база: пользователи, проекты, очередь задач | всегда |
| `minio`, `minio-init` | объектное хранилище (`pgsty/minio`, с веб-консолью) и одноразовое создание закрытого бакета | всегда |
| `languagetool-1`, `languagetool-2` | две реплики проверки текста | `services` |
| `onlyoffice` | редактор офисных файлов | `services` |
| `ollama` | локальные модели | `ai` |

Redis не нужен: очередь задач работает на Postgres.

## Запуск

```bash
cd deploy/server
cp .env.example .env     # заполните обязательные значения, подсказки внутри файла
sudo mkdir -p /var/lib/hse-runner   # каталог раннера
sudo chown 10001:10001 /var/lib/hse-runner   # владелец: пользователь app образа
docker compose up -d
docker compose --profile services up -d      # добавить LanguageTool и ONLYOFFICE
```

Реплики из профиля `services` подключаются к api переменными `LANGUAGETOOL_REPLICAS` и `OFFICE_EDITOR_REPLICAS`
в `.env` (значения в комментариях `.env.example`); пока списки пусты, проверка текста и редактор недоступны.

Каталог раннера принадлежит пользователю `app` внутри образа. Узнать его uid и gid:
`docker run --rm --entrypoint id ghcr.io/alexeyshalaev/hse-doc-studio app`.
Один раннер на хост и каталог данных: токен регистрации одноразовый, `--scale runner=N` не поддерживается.
Дополнительные раннеры запускайте на других машинах со своими токенами из админки.

api слушает только `127.0.0.1` (`BIND_ADDRESS` в `.env`): обратный прокси с TLS должен работать на том же хосте,
иначе задайте `BIND_ADDRESS` явно.

Проверка файла без запуска: `docker compose config -q`; все профили сразу:
`docker compose --profile services --profile ai config -q`.

## Первый вход

1. Откройте `PUBLIC_URL`. Пока администратора нет, Студия показывает мастер первого запуска.
2. Токен установки печатается в журнале api: `docker compose logs api | grep -i setup`.
3. Создайте администратора, задайте режим регистрации и (если нужна) почту.
4. В админке на странице раннеров проверьте, что раннер зарегистрирован и берёт задачи.

Администратора можно создать и без мастера: задайте в окружении api
`HSE_STUDIO__AUTH__ADMIN_EMAIL` и `HSE_STUDIO__AUTH__ADMIN_PASSWORD` (или `..._PASSWORD_FILE`).

api стартует в `server`, только когда реестр готовности зелёный; если нет, отказ называет всё недостающее
(например, `HSE_STUDIO__DB__DSN`, `HSE_STUDIO__AUTH__PUBLIC_URL`, ключ секретов). Полный список настроек api:
`docs/ru/deploy/env-reference.md`, настройки раннера лежат в `HSE_RUNNER__*`.

## Токен раннера

`RUNNER_BOOTSTRAP_TOKEN` нужен один раз. api кладёт в базу его хеш при старте, раннер меняет его на
собственный токен и записывает в `identity.json` своего каталога данных. После этого значение можно
убрать из `.env`, но раннеры, которые запускаются впервые, снова потребуют токен. Новые раннеры на
других машинах регистрируются токеном, выпущенным в админке.

## Безопасность раннера

- `/var/run/docker.sock` подключён только сервису `runner`; у api доступа к докеру нет.
- Сокет эквивалентен root на хосте. Раннер-хост считайте доверенной инфраструктурой: лучше rootless
  docker, sysbox или отдельная виртуальная машина, не машина с другими сервисами.
- Токен раннера и токены задач не передаются в контейнер сборки.
- Раннер в этом наборе один на хост; раннер под Kubernetes (под на задачу) относится к следующим этапам.

## Консоль и метрики MinIO

Хранилище работает на образе `pgsty/minio` (форк MinIO с возвращённой веб-консолью; в upstream-образах с Docker Hub консоли управления больше нет). Тег закреплён по версии (`RELEASE.2026-08-04T00-00-00Z`), клиент `mc` лежит в том же образе, поэтому `minio-init` использует его же.

- Консоль: `http://127.0.0.1:19001` на хосте (`MINIO_CONSOLE_BIND`, `MINIO_CONSOLE_PORT`). Вход: `S3_ACCESS_KEY` и `S3_SECRET_KEY` из `.env` (учётка администратора MinIO). Там видны бакеты, пользователи и метрики. Порт слушает только loopback: с другой машины используйте SSH-туннель `ssh -L 19001:127.0.0.1:19001 host` или обратный прокси с аутентификацией и поддержкой WebSocket. Наружу без прокси его не открывайте.
- Порт S3 (9000) наружу не публикуется, api ходит к нему по внутренней сети compose.
- Метрики Prometheus: `/minio/v2/metrics/cluster` (также `/node`, `/bucket`, `/resource`) на порту 9000. По умолчанию `MINIO_PROMETHEUS_AUTH_TYPE=public`: токен не нужен, а порт доступен только внутри сети compose. Скрейпить можно Prometheus, подключённым к этой сети: `static_configs: [{targets: ["minio:9000"]}]`, `metrics_path: /minio/v2/metrics/cluster`. Разовая проверка: `docker compose exec minio curl -s localhost:9000/minio/v2/metrics/cluster | head`. Если скрейп идёт через сеть хоста, задайте `MINIO_PROMETHEUS_AUTH_TYPE=jwt`, получите токен `docker compose exec minio mc admin prometheus generate local` и передайте его в `bearer_token` задания Prometheus.

## Обратный прокси и долгий опрос

Раннер держит запрос опроса до 25 секунд. Перед api задайте read-timeout не меньше 60 секунд и
отключите буферизацию ответов (nginx: `proxy_read_timeout 75s; proxy_buffering off; client_max_body_size 512m;`).
Не забудьте указать адрес прокси в `TRUSTED_PROXIES`.

Загрузка проекта (`POST /projects/import`) идёт большим телом. Поднимите `client_max_body_size` до значения
`HSE_STUDIO__SERVER__PROJECT_IMPORT_MAX_BYTES` плюс запас около 1 МБ (по умолчанию `client_max_body_size 501m;`).
Само api обрывает слишком большое тело с 413 ещё до записи во временный файл.

## Совместная правка (WebSocket)

Редактор исходников держит сокет `/api/collab/v1/projects/<id>/room` (протокол y-websocket поверх WebSocket).
Прокси должен пропускать `Upgrade`/`Connection` (nginx: `proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection $connection_upgrade;`) и не рвать молчащее соединение раньше 60 секунд: клиент шлёт
присутствие каждые 15 секунд. Сервер сверяет Origin с `PUBLIC_URL`, поэтому прокси обязан сохранять заголовки
`Origin` и `Host`. Документ закреплён за репликой api: при нескольких репликах или воркерах направляйте
подключения к одному файлу на одну реплику (sticky по `project` и `path`), иначе правки видны друг другу с задержкой
в секунду, а курсоры не общие. Выключить: `HSE_STUDIO__COLLAB__ENABLED=false`, пределы: `HSE_STUDIO__COLLAB__*`.

## Личные раннеры

Люди могут подключать свои машины как личные раннеры («Мои раннеры» в настройках аккаунта): такой раннер собирает только проекты своего хозяина, сборки на нём не тратят квоты установки, а при его недоступности сборка уходит на общие раннеры. Админ видит личные раннеры в `/admin/runners`, может приостановить и отозвать их и выключить личные раннеры на всю установку (`HSE_STUDIO__JOBS__PERSONAL_RUNNERS_ENABLED=false` или переключатель в настройках сборки). Окно ожидания личного раннера и предел раннеров на человека задают `HSE_STUDIO__JOBS__PERSONAL_RUNNER_WAIT_S` (по умолчанию 5 с) и `HSE_STUDIO__JOBS__PERSONAL_RUNNERS_MAX_PER_USER` (по умолчанию 5). Оверлей `compose.personal.yml` нужен только живому стенду e2e.

## Обновление и бэкап

Обновление: смените `TAG`, затем `docker compose pull && docker compose up -d`. Миграции базы выполняет
api на старте под advisory-локом, совместимость версий api и раннера проверяется при регистрации.

Бэкап:

- база: `docker compose exec -T postgres pg_dump -U studio studio > studio.sql`;
- тома `minio-data` (блобы и выходы сборки), `api-data` (исходники проектов, `users/**` с ролями агента и `gnupg/` со связкой OpenPGP: копируйте том целиком) и `onlyoffice-data`;
- `SECRETS_KEY` отдельно от дампов: без него секреты в базе не прочитать.
