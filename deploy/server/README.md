# Общий сервер HSE Doc Studio (docker compose)

Развёртывание серверного режима на одной машине: api, раннер задач, Postgres, MinIO (S3) и по желанию
два LanguageTool, ONLYOFFICE и Ollama. Локальная установка для одного пользователя живёт отдельно
в `deploy/all-in-one`.

## Состав

| Сервис | Назначение | Профиль |
|---|---|---|
| `api` | веб-интерфейс и API, режим `server`, миграции базы на старте | всегда |
| `runner` | берёт задачи у api, собирает документы в соседних контейнерах | всегда |
| `postgres` | база: пользователи, проекты, очередь задач | всегда |
| `minio`, `minio-init` | объектное хранилище и одноразовое создание закрытого бакета | всегда |
| `languagetool-1`, `languagetool-2` | две реплики проверки текста | `services` |
| `onlyoffice` | редактор офисных файлов | `services` |
| `ollama` | локальные модели | `ai` |

Redis не нужен: очередь задач работает на Postgres.

## Запуск

```bash
cd deploy/server
cp .env.example .env     # заполните обязательные значения, подсказки внутри файла
sudo mkdir -p /var/lib/hse-runner   # каталог раннера, владелец см. ниже
docker compose up -d
docker compose --profile services up -d      # добавить LanguageTool и ONLYOFFICE
docker compose up -d --scale runner=3        # три раннера
```

Реплики из профиля `services` подключаются к api переменными `LANGUAGETOOL_REPLICAS` и `OFFICE_EDITOR_REPLICAS`
в `.env` (значения в комментариях `.env.example`); пока списки пусты, проверка текста и редактор недоступны.

Каталог раннера принадлежит пользователю `app` внутри образа. Узнать его uid и gid:
`docker run --rm --entrypoint id ghcr.io/alexeyshalaev/hse-doc-studio app`.
При нескольких репликах `--scale runner=N` у каждой должен быть свой каталог данных: используйте
отдельные compose-проекты или запускайте раннеры на разных машинах.

Проверка файла без запуска: `docker compose config -q`; все профили сразу:
`docker compose --profile services --profile ai config -q`.

## Первый вход

1. Откройте `PUBLIC_URL`. Пока администратора нет, Студия показывает мастер первого запуска.
2. Токен установки печатается в журнале api: `docker compose logs api | grep -i setup`.
3. Создайте администратора, задайте режим регистрации и (если нужна) почту.
4. В админке на странице раннеров проверьте, что раннер зарегистрирован и берёт задачи.

Администратора можно создать и без мастера: задайте в окружении api
`HSE_STUDIO__AUTH__ADMIN_EMAIL` и `HSE_STUDIO__AUTH__ADMIN_PASSWORD` (или `..._PASSWORD_FILE`).

api стартует в `server`, только когда реестр готовности зелёный; если нет, отказ называет всё недостающее
(например, `HSE_STUDIO__DB__DSN`, `HSE_STUDIO__AUTH__PUBLIC_URL`, ключ секретов). Полный список настроек api:
`docs/ru/deploy/env-reference.md`, настройки раннера лежат в `HSE_RUNNER__*`.

## Токен раннера

`RUNNER_BOOTSTRAP_TOKEN` нужен один раз. api кладёт в базу его хеш при старте, раннер меняет его на
собственный токен и записывает в `identity.json` своего каталога данных. После этого значение можно
убрать из `.env`, но раннеры, которые запускаются впервые, снова потребуют токен. Новые раннеры на
других машинах регистрируются токеном, выпущенным в админке.

## Безопасность раннера

- `/var/run/docker.sock` подключён только сервису `runner`; у api доступа к докеру нет.
- Сокет эквивалентен root на хосте. Раннер-хост считайте доверенной инфраструктурой: лучше rootless
  docker, sysbox или отдельная виртуальная машина, не машина с другими сервисами.
- Токен раннера и токены задач не передаются в контейнер сборки.
- Раннер в этом наборе один на хост; раннер под Kubernetes (под на задачу) относится к следующим этапам.

## Обратный прокси и долгий опрос

Раннер держит запрос опроса до 25 секунд. Перед api задайте read-timeout не меньше 60 секунд и
отключите буферизацию ответов (nginx: `proxy_read_timeout 75s; proxy_buffering off;`).
Не забудьте указать адрес прокси в `TRUSTED_PROXIES`.

Загрузка проекта (`POST /projects/import`) идёт большим телом. Поднимите `client_max_body_size` до значения
`HSE_STUDIO__SERVER__PROJECT_IMPORT_MAX_BYTES` плюс запас около 1 МБ (по умолчанию `client_max_body_size 501m;`).
Само api обрывает слишком большое тело с 413 ещё до записи во временный файл.

## Обновление и бэкап

Обновление: смените `TAG`, затем `docker compose pull && docker compose up -d`. Миграции базы выполняет
api на старте под advisory-локом, совместимость версий api и раннера проверяется при регистрации.

Бэкап:

- база: `docker compose exec postgres pg_dump -U studio studio > studio.sql`;
- тома `minio-data` (блобы и выходы сборки), `api-data` (исходники проектов, `users/**` с ролями агента и `gnupg/` со связкой OpenPGP: копируйте том целиком) и `onlyoffice-data`;
- `SECRETS_KEY` отдельно от дампов: без него секреты в базе не прочитать.
