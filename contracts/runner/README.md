# Контракт раннера

Общие файлы API и раннера: протокол pull поверх HTTPS JSON под `/api/runner/v1`. Расхождение сторон ловит `services/api/tests/unit/contract/test_runner_contract.py`:

- `openapi.yaml` описание вызовов (регистрация, долгий опрос, пульс, лог, блобы, выходы, итог) и схем; схемы совпадают по полям, обязательности и перечислениям с `api/schemas/runner.py` (`extra=forbid`);
- `error_codes.json` закрытый список кодов ошибок (тело `{detail, code}`), совпадает с `RunnerErrorCode` и `x-error-codes`;
- `fixtures/<Схема>/<вариант>.json` эталонные тела; каждое проходит строгую модель и совпадает после круга через проводные датаклассы `core/jobs/wire.py` и `codec`. Конверт покрыт для каждого вида задачи. Вложенные схемы (`ActorWire`, `JobSpecWire`, `JobResultWire`, `BlobLocationBody`) отдельных эталонов не имеют.

Конверт несёт снимок актора и его роль в проекте на момент постановки (`actor_role`): применение результата пересобирает актора по ним, а не берёт системного. Каждый вызов по задаче несёт `attempt`, устаревшая попытка получает 409 `stale_attempt`.

Форму меняют так: сначала `openapi.yaml` и эталоны, затем `wire.py`, pydantic-схемы и тесты в одном коммите.
